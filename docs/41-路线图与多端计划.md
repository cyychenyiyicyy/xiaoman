# 41 · 路线图与多端计划（alpha 之后）

> 2026-11-19。alpha 0.1 之后的方向记录。**除“当前优先级”外，本文所有多端项目均为暂缓**，不排期、不占 alpha 的验收。

---

## 0. alpha 0.1 的边界

已经有的：

- 平板优先的 MD3 Web 界面（1280×800 / 800×1280 / 1024×768）；
- FastAPI + PostgreSQL + Pi 网关；
- 题库 / 知识点 / 知识地图 / FSRS 复习 / 资料 / 记忆 / 本周；
- 首次引导（agent 名字 + 用户名字 / 性别 / 年级）；
- Android 系统 WebView 壳 + GitHub Actions debug APK；
- 拍题默认自动矫正，复核框按原图坐标。

alpha 不做的：多端同步、桌面端、Linux 服务端、多用户、班级、分享、应用商店上架。

---

## 1. 多端互联（暂缓）

### 目标

平板、手机、桌面看到同一份对话 / 题库 / 复习队列 / 资料 / 记忆；“在哪台设备上继续”不需要导出导入。

### 最小方案

服务器已经是唯一权威源：

```
设备 A ─┐
设备 B ─┼── HTTP/SSE ── FastAPI ── PostgreSQL
设备 C ─┘
```

- **鉴权**：单用户也必须有。首选 Tailscale 组网 + 应用层 `APP_TOKEN`；公网只开反代，不裸奔。
- **增量同步**：
  - 每张表带 `updated_at` / `rev`，客户端保存 `cursor`；
  - `GET /sync?since=<cursor>` 拉变更，`POST /sync` 推本地离线产生的 `review_log` / 草稿；
  - 单用户冲突很少：服务器优先，客户端把冲突条目留在“待处理”。
- **离线**：复习队列可提前下发未来 3 天；评分先写本地 `review_log`，联网回放。
- **图片 / 资料**：对象存储或服务器文件 + 内容哈希去重；不在设备间直接 P2P。

### 触发条件

- 手机端开始真正用于“看今天安排 / 快速问一句”；
- 或平板与桌面同时使用，出现手工导出导入。

### 不做什么

- 不做实时协同编辑（单用户不需要 CRDT）；
- 不做账号注册 / 多租户；
- 不做端到端加密（服务器本来就是自己的）。

---

## 2. Windows 桌面版（暂缓）

### 形态

轻量壳 + 同一套 Web UI，不重写界面。

候选：

| 方案 | 优点 | 风险 |
|---|---|---|
| **WebView2 壳**（WinUI/WPF） | Windows 自带运行时、体积小、性能接近 Edge | 只覆盖 Windows |
| **Tauri**（WebView2） | 跨平台、打包小、Rust 后端可做本地能力 | 引入 Rust 工具链 |
| Electron | 生态最熟 | 包体大、内存高，和“永久项目、低依赖”冲突 |

倾向：**Tauri 或原生 WebView2 壳**，复用 `web/`；本地文件、托盘、开机自启、系统通知按需加。

### 触发条件

- 主要在电脑上整理题库 / 看知识地图 / 写长内容；
- 平板输入效率成为瓶颈。

---

## 3. Linux 桌面端 + Linux 服务器端（暂缓）

两者**不是同一个东西**：

| | 桌面端 | 服务器端 |
|---|---|---|
| 界面 | 有 | **无** |
| 主要用途 | 本地使用、离线缓存、桌面通知 | 跑 API / Pi 网关 / 定时复习 / 同步 |
| 壳 | Tauri（WebKitGTK）或 WebView | 无 |
| 部署 | AppImage / deb | Docker Compose / systemd |

服务器端可以直接复用现有 `server/` + `agent/`，加：
- Dockerfile / compose（PostgreSQL + API + Pi 网关 + Caddy）；
- systemd 单元；
- 备份脚本（`pg_dump` + 资料目录）；
- 只读周报页（可选）。

桌面端复用同一套 Web UI，补 Linux 的文件选择 / 通知 / 托盘。

### 触发条件

- 服务器迁移到 Linux；
- 或需要一台常开的低功耗机器跑复习调度。

---

## 4. 当前优先级（alpha 打磨）

1. **首次引导的细节**：agent 名字在更多文案里生效；资料编辑入口；空名字的兜底。
2. **拍题准确率**：自动矫正默认开之后的复核框、跨页题、手写题；失败退路。
3. **Android 兼容**：目标学习机 WebView 版本核对；旧 Chromium 的降级样式。
4. **错误恢复**：断网、网关 401、模型 400、任务卡住时的明确提示与重试。
5. **测试**：`server/tests/verify.py`、web smoke、Android 构建三条线保持绿。

---

## 5. 顺序建议

```
alpha 打磨
  └─ 多端互联（先鉴权 + 增量同步，不碰 UI 结构）
       ├─ Windows 壳（复用 Web UI）
       └─ Linux 服务器端（Docker + 备份）
            └─ Linux 桌面端（最后，收益最小）
```

**不要**为了“多端”先重写前端框架；现在的 Web UI 已经是多端共用的资产。
