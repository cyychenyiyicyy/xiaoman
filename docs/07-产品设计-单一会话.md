# 07 · 产品设计：一个对话，一个伙伴

> 用户的定位：**"我想要的是一个可以一直陪伴你学习、帮助你学习、赋能你的学习的老师或者伙伴。"**
> 本文是这个定位的产品设计：手机端**只有一个对话，没有会话列表**。

---

## 1. 先验证你说的那件事：调研结论

你说「personal agent 没有会话列表，一个会话像微信好友一样一直聊下去」。**这不是偏好，是这个品类的共同形态**，而且证据很硬：

| 来源 | 原文/要点 |
|---|---|
| **Meta Muse**（2026-09） | 「Muse 的主聊天界面，被设计成**一段持续的长对话，就像你和另一个人交谈那样**。和其他 AI 应用不同……团队有意识地划定了哪些地方必须使用明确的界面控件，**带有清晰「接受／拒绝」选项的结构化审批卡片**」（[极客公园/Founder Park](https://w.geekpark.net/news/371795#1)） |
| **ownAI**（开源，2026-02） | 核心需求第一条：**"Continuous Conversation — No 'sessions' or 'chats' - one flowing conversation per AI instance"**，配套**分层记忆**（working memory / summaries / long-term vector store），靠 intelligent summarization 做到无限历史（[ownAI projectbrief](https://codeberg.org/ownAI/ownAI/src/commit/d457f45d23c7ee05efc9beeaadb832436c7a0c85/memory-bank/projectbrief.md)） |
| **MIRA**（2026-11） | 「built around the premise that the user talks to **one assistant in one thread**」，且带一个 collapse hook 做记忆压缩（[agent-memory-atlas](https://github.com/neoneye/agent-memory-atlas/blob/21afbd103c6e6097db5df307921dfafad7b121e8/docs/systems/mira/index.html)） |
| **Inflection Pi** | 跨会话记忆，但**主动跳过临时、一次性、对未来没用的内容**（[Pi Memory](https://help.pi.ai/en/articles/15425697-pi-s-memory)） |

**三条可提炼的规律：**

1. **单一会话是主流形态**，不是新潮做法——因为你不会跟"一个朋友"开十个会话。
2. **单一会话的代价是上下文无限膨胀**，所以上面每一个都配了**分层记忆**。这不是可选项，是单一会话的必要条件。
3. **动作类的东西要用结构化卡片，不要靠自然语言按钮**。Muse 的原话：涉及审批/操作的地方「必须使用明确的界面控件」，卡片上写清「接受／拒绝」。

> 第 2 条是本文的技术核心（§6），第 3 条直接决定了我们的**消息类型系统**（§4）。

## 2. 职责重述（你上一条说得对，这里定死）

| 端 | 职责 | **不做什么** |
|---|---|---|
| **服务器** | Pi 网关（转发） + 工具实现（~20 个） + 确定性业务（FSRS 调度 / 知识图谱 / 错题 / 统计） | 不做界面逻辑、不做消息排版、不猜用户意图 |
| **手机** | 一个对话流 + 卡片渲染 + 本地缓存 + 接收推送 + 离线发送队列 | 不做调度计算、不做 OCR、**不存权威数据** |

一句话：**手机端不是"一个带聊天功能的 App"，而是"App 就是一个对话框"。**

---

## 3. 核心设计决定：功能不是 Tab，是**消息的展开**

这是单一会话能不能成立的分水岭。

如果功能是并排的 Tab（今日/采集/图谱/错题/统计），那"单一会话"就只是聊天页 + 五个页面，等于没做。**手机屏幕底部因此不设 Tab 栏。**

**做法：所有功能以「卡片消息」出现在流里，点卡片展开成全屏。**

| 你做什么 | 她回什么 | 点开是什么 |
|---|---|---|
| 拍了一页卷子 | `capture_card`：识别到 3 道题，1 道待确认 | 全屏校对页 |
| 说「我要复习」 | `review_card`：今天 12 张 + 3 道错题 | 全屏沉浸复习（一卡一屏） |
| 问「电磁感应老错的根因」 | 文本 + `kp_chain_card`：先修链 + 掌握度 | 知识地图（聚焦这条链） |
| 周日晚上 | `digest_card`：本周周报 | 热力图 / 重犯率 |
| 她想改你的库 | `confirm_card`：**接受 / 拒绝** | — |
| 翻旧账 | 左滑抽屉：错题本 / 知识地图 / 统计 / 设置 | 独立页 |

**副作用（很好）**：功能页不再是"入口"，而是"某条消息的详情"。你就不会在首页纠结"我今天该点哪个"——**首页只有一句话，和她的名字。**

## 4. 消息类型系统（8 种，一张表定义整个产品）

| # | type | 内容 | 可展开 | 出现方式 |
|---|---|---|---|---|
| 1 | `text` | 普通对话，Markdown + LaTeX | — | 双向 |
| 2 | `image` | 你发的照片 / 她截的图 | 全屏查看 | 双向 |
| 3 | `capture_card` | 识别结果：n 题、m 待确认、置信度 | → 校对页 | 你拍完后 |
| 4 | `review_card` | 今日队列（到期卡 + 待重做错题） | → 沉浸复习 | 她说「开始」/ 你问 |
| 5 | `question_card` | 单题卡：题干 + 你上次错在哪 + 做几次 | → 题目详情 | 检索/讲解时 |
| 6 | `kp_chain_card` | 先修链 + 每节掌握度色块 | → 知识地图 | 「根因」类提问 |
| 7 | `digest_card` | 周报：量、掌握度升降 Top3、重犯错因 | → 统计页 | 每周日 |
| 8 | `confirm_card` | **待确认写入**：她要改库，列 diff，「接受/拒绝」 | — | 写工具被闸门拦下时 |

**第 8 种是全篇最重要的工程约定。** 06 里说「写操作默认落待确认队列」——`confirm_card` 就是那个队列的界面形态。Muse 团队的结论和我们一致：**涉及改数据的地方，必须给明确的接受/拒绝，不能靠模型在自然语言里"问一句"**。

> 附加规则：**任何一条卡片消息都必须能降级成纯文本**（离线/旧客户端时）。消息 schema 里 `payload_json` 之外必须保留 `fallback_text`。

│  │      [ 接受 ]   [ 拒绝 ]     │      │
│  └────────────────────────────┘      │
│                                      │
├──────────────────────────────────────┤

**四条界面硬规则：**

1. **顶栏不显示"会话标题"**，显示「她 + 今天在陪你学什么」。没有"新建会话"按钮。
2. **没有返回键能回到"会话列表"**——因为没有会话列表。左滑是抽屉（错题/地图/统计/设置）。
3. **输入区只有 4 个动作**：＋（更多）· 拍照 · 语音 · 文字。**拍照是第二显眼的位置**，因为纸质是你的主要输入。
4. **消息气泡左她右你**，头像固定，风格稳定——这是「像个人」的物理基础。

## 6. 单线程怎么不爆：三层记忆（技术核心）

**问题**：一年后这个对话有几十万条消息。Pi 的 compaction 只能压"当前 session"，压不住"一整年"。

**解法：历史不是被"记住"，是被"索引"。**

| 层 | 存哪 | 内容 | 谁维护 | 生命周期 |
|---|---|---|---|---|
| **① 工作记忆** | Pi session（compaction） | 最近 K 轮原文 + 压缩摘要 | **Pi 自动**（reserveTokens 16384 / keepRecentTokens 20000） | 会话级 |
| **② 事件摘要** | 你的 DB（新表 `event`） | 每次会话结束一条：主题 / 结论 / 待办 / 涉及知识点 | 网关的异步任务 | 永久，可检索 |
| **③ 结构化事实** | 你的 DB（8 张表） | 知识点掌握度、错题、复习历史、题目 | 工具读写 | 永久，权威 |

**每次提问的上下文组装：**

```
系统提示（人设 + 规则）
+ 当前学科 + 今天日期
+ 最近 K 轮原文（①）
+ 相关事件摘要 Top-3（②，按语义/知识点检索）
……注意：结构化事实不前置注入，而是让 agent 用工具现查（③）
```

第三条是关键：**不要把错题列表塞进 prompt，让它调 `mistake_list`。** 这样上下文恒定，且答案永远基于当下的真实数据。

**必须加的一条运维动作：每周归档。** 把 30 天前的原文压成 `event` 摘要，只留摘要 + 索引。没有这一步，第二年就会慢到不可用。

## 7. 多学科怎么处理

> **修订（2026-11-14）**：本节初版推荐「方案 B：**消息流合并渲染**」。用户指出"九科的会话全混在一起不好"——**这个质疑成立，B 已废弃**。定稿为 **方案 D「学科空间」**，详见 **[11-学科空间设计.md](11-学科空间设计.md)**。
>
> 差别的唯一实质：**不做合并渲染**。一次只显示一个学科的消息。本文其它内容（无会话列表、8 种消息类型、三层记忆、主动消息边界、冷启动）**全部不变**。

| 方案 | 做法 | 判断 |
|---|---|---|
| A | 真的一个 Pi session，靠 agent 自己判断你在学哪科 | ❌ 上下文互相污染，compaction 会把数学和英语混在一起压 |
| ~~B~~ | ~~界面一个对话，内部按学科分 session，**消息流合并渲染**~~ | ❌ **已废弃**——合并渲染就是"混在一起"，往下翻会插进别的科 |
| C | 按学科分会话 + 界面显示会话列表 | ❌ 这是会话列表，否决 |
| **D** | **学科空间**：顶部学科胶囊切十个空间；每个空间内是**一条无限长的连续对话**；**不做合并渲染** | ✅ **定稿** |

**方案 D 的四条要点**：

1. **关系轴单一，内容轴分科**——只有一个她（人格/语气/记忆），但有九个各自往下长的空间；
2. **切换 = 换空间，不是"新建对话"**：没有新建、没有删除、历史永远在。所以**仍然不是会话列表**；
3. **「全部」是默认落地页**，而且**长得像对话**（她今早的那段话 + 四张科目摘要卡），不是仪表盘；
4. **记忆面板 / 复习队列 / 知识地图 / 错题本 / 本周 = 全局**，不按科拆（"今天练什么"是全局问题）。

**跨学科提问**：在物理空间问"这题要用到数学的什么"→ **不切空间**，当前 session 回答，工具跨库查，引用处标 `来自数学` 的 chip。要换科必须显式（你说，或你点胶囊）。

## 8. 她会主动找你（陪伴感的真正来源）

**这是"工具"和"伙伴"的唯一实质区别。** 但"主动"最容易做坏——做成催收就毁了。

### 8.1 四种主动消息

| 类型 | 时机 | 内容要求 | 频率上限 |
|---|---|---|---|
| **每日开场** | 你设的时间（默认 07:30，可关） | **只写今天的三件事，不超过 3 行** + 一个 review_card | 1/天 |
| **遗忘预警** | 某高价值知识点掌握度跌破阈值 **且** ≥14 天未触碰 | 必须带**具体数字**和**一个 5 分钟的动作**：「楞次定律 0.42，21 天没碰，现在花 5 分钟？」 | 1/天，同一点 7 天内不重复 |
| **周报** | 周日 20:00 | 量 + 升降 Top3 + 重犯错因 | 1/周 |
| **断签** | 连续 3 天没有交互 | 一句，不带愧疚绑架（"在忙就先忙，回来我给你留了 4 张卡"） | 1 次，之后静默 |

### 8.2 四条不可越的边界

1. **一天最多 2 条主动消息**（每日开场算 1 条，预警和周报算另 1 条，超出顺延）；
2. 任何一条都能「**今天别烦我**」，当天不再推；
3. **不做游戏化**：没有连续天数徽章、没有排行榜、没有"你已坚持 N 天"的炫耀；
4. **没有消息时不硬找话**。静默是这个产品的正常状态。

### 8.3 主动消息必须是"判断"，不是"提醒"

- ❌ 「你有 12 张卡待复习」（定时器就能做，没有价值）
- ✅ 「12 张里 7 张是电磁感应，你上次这块错了 3 次。先把最上面那层补了，后面会顺」（读完你的数据才做得出）

## 9. 冷启动：第一周她怎么"认识"你

**Day 0（第一次打开）**：不问长问卷，只问三个：

1. 你在学什么？（学科 + 学段）
2. 什么时候要考 / 学到哪儿算完？
3. 每天大概能给几分钟？（5 / 15 / 30）

→ 然后立刻给她能做的第一件事：**"先拍一页你现在手上的卷子，我帮你把它拆成题。"** 用一次真实的成功建立信任，比任何引导页都有效。

**Day 1–7**：每次交互后写一条「她记住的」，落在**记忆面板**（抽屉里）：
- 每条一句话，可见、可改、可删；
- 只记两类：**稳定的学习事实**（"电磁感应薄弱，根因在磁场对电流的作用"）+ **稳定偏好**（"喜欢先看提示不给完整答案"）；
- **不记**闲聊、临时情绪、一次性内容（呼应 Inflection Pi 的做法）。

> **记忆可见是这个产品信任的地基。** 一个"记得你但你不记得它记了什么"的 AI，会让人不安。所以你随时能翻、能删。

## 10. 让它像"伙伴"而不是"工具"的具体清单

| 要素 | 具体做法 |
|---|---|
| **有身份** | 起个名字（不是"AI 助手"），固定头像，稳定语气 |
| **说话短** | 一条消息 ≤ 4 行，讲解分级（先提示，再详解，要展开才展开） |
| **记得上次** | 开口能接："上次那道电磁感应，你后来做对了" |
| **不重复问** | 记忆面板里有的，不再问第二遍 |
| **会承认不知道** | "这个知识点我库里还没有，要不要现在建一个？"（而不是编） |
| **不刷存在感** | 没事就不说话（§8.2 第 4 条） |
| **语气** | 老师/伙伴，不是客服。禁止"您好，请问有什么可以帮您"这种腔调 |
| **不评判** | 错了不渲染情绪，"错因是读题，不是不会"——把错归到机制上，不归到人 |

## 12. 技术落点（Compose）

```kotlin
// 消息表（Room）——单一会话，所以没有 session_id 外键，只有 subject
@Entity data class Message(
  @PrimaryKey val id: String,          // 本地 ULID
  val serverId: String?,               // 服务端 entry id（增量游标）
  val role: String,                    // user | agent
  val type: String,                    // text|image|capture_card|review_card|…
  val payloadJson: String,             // 结构化载荷
  val fallbackText: String,            // 降级/离线可读
  val subject: String?,
  val ts: Long,
  val status: String                   // sending|streaming|sent|failed
)
```

| 事项 | 做法 |
|---|---|
| **增量同步** | `GET /agent/entries?since=<serverId>`，服务端 entry id 是持久游标 |
| **流式** | SSE，token 追加到当前 `streaming` 消息，光标动画；`tool_start/tool_end` 事件渲染成"正在查你的错题本…"的瞬态提示 |
| **离线** | 已收到消息全在 Room；发送走 outbox + 幂等 `op_id`；复习可离线（预下发 3 天队列） |
| **渲染** | Markdown（Markwon）+ LaTeX（MathJax in WebView，或轻量 jlatexmath）；卡片是普通 Composable |
| **推送** | ntfy（自建）只负责"把她叫醒"；**点开是对话，不是功能页** |
| **深色/主题** | M3 动态取色；气泡色用 `surfaceContainer` 系列，不自己配 |

## 13. 第一阶段砍到什么程度（最小可用的"她"）

先只做这五样，**就足以判断"这个伙伴成不成立"**：

1. **单一会话流** + `text` 消息 + 流式（含 Markdown/LaTeX）
2. **拍照 → `capture_card`**（纸质进得来，这是你的命门）
3. **`review_card` + 全屏复习**（12 张卡能真的做完）
4. **`confirm_card`**（她改库前必须问过你）
5. **每日开场主动消息**（她会主动找你 —— 没有这条，她就只是个对话框）

> `kp_chain_card`、`digest_card`、抽屉里的三张长周期视图，全部后置到第二阶段。**先证明"一个人愿意每天跟它说话"，再证明"它很聪明"。**

---

## 14. 一句话总结

> **她不是"你打开的一个 App"，是"一个会先开口的人"。**
> 手机端只有一个对话、一个名字、一条时间线；所有功能都是她递给你的卡片；你不说话的时候她不吵你，但该来的时候她会来。
