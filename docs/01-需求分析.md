## 0. 一句话定义

> **把散在纸上、散在对话里的学习痕迹，收成一个会自己找上门的知识体。**

三个动词是产品的全部：**收进来**（纸质/对话/网页）→ **连起来**（题目 ↔ 知识点 ↔ 先修）→ **推回去**（按遗忘曲线主动回到你面前）。

你描述的「贴心、时时关心、记录变化、帮整理、帮复习」，翻译成工程语言就是：**有持久记忆 + 有主动发起权 + 有对你个人数据的读写权**。这正是 personal agent 与聊天框的分界线——聊天框等你问，agent 替你记。

### 0.1 学段与科目范围（2026-11-14 已确认）

> **高一 · 九科全开**（语文 / 数学 / 英语 / 物理 / 化学 / 生物 / 政治 / 历史 / 地理）。

三个必须现在就知道的后果：

| # | 后果 | 应对 |
|---|---|---|
| **1** | **知识点树要建 9 份**，不是 1 份。现成数据集几乎只有数学（`cn-math-taxonomy` 1644 个知识点 + 2403 条先修边） | **数据模型第一天就是多学科**（`kp.subject` + 每科一棵树）；知识树**按需建**，不做一次性铺全 |
| **2** | **M1 先跑通一科，不是九科**。建议 **物理**（你现在最痛，且公式链路与数学同源） | 照 `cn-math-taxonomy` 的结构自己录物理必修一：力、受力分析、牛顿三定律…… 约 120–180 个知识点就够高一上学期 |
| **3** | **复习队列必须跨科混排**，否则每天要开九个入口 | 队列按「紧急度 + 每日预算」混排，不按科目分组；顶部只显示"今天主要在物理" |

> 好消息：九科在**产品形态上不增加任何界面**。单一会话 + 学科切换（07 §7 方案 B）已经能承载——她只要知道你"现在在学哪科"就够了。

## 1. 原始诉求 → 真实需求

你说的五件事，表层是「功能」，底层是「机制」。逐条对齐：

| # | 你的原话 | 表层需求 | 真实需求（机制层） | 对应系统能力 |
|---|---|---|---|---|
| 1 | 纸质版内容过多，整理起来非常麻烦 | 一个电子归档 | **不是「存起来」，是「存完还能被用上」。** 归档若不参与检索与复习，只是换个地方躺着 | 采集 → 结构化 → 入库 → 可检索 |
| 2 | 想找以前做过哪一题 | 搜索框 | **记忆是模糊的**。你不会记得题干原文，只记得「那道带电粒子在磁场里转的题」 | 图搜题 + 向量语义召回 + 知识点/错因/时间多维过滤 |
| 3 | 知识点串联麻烦 | 知识图谱 | **不是画得好看**，而是「我错在 A，根因其实在 B」这种**先修关系**，以及「这个点我只在第三章见过」 | 知识点树 + 先修有向边 + 题目↔知识点多对多 + 掌握度沿边传播 |
| 4 | 错题收集非常麻烦 | 错题本 | **抄一遍太贵，所以不抄。** 且「错题」不是静态清单，是**可重做、可判分、可统计重犯率**的过程 | attempt 记录 + 错因标签 + 变式题生成 + 重犯率统计 |
| 5 | 问 AI 只给答案，不会把「我不会的」记下来做图谱关联 | 对话沉淀 | **每一次「我去问 AI」本身就是最真实的薄弱点信号**——你只有在不会的时候才会问。现在的 AI 把这颗信号丢掉了 | **对话即采集**：问答结束自动抽取「卡住的知识点」→ 落库 → 关联 → 进复习队列 |

**第 5 条是这个产品最锋利的差异化**，也是你和 Anki、NotebookLM、作业帮三者都不一样的地方：
- Anki 要你**先知道自己不会什么**，再手工造卡；
- NotebookLM 能读资料，但**不产生复习行为**；
- 作业帮给你答案，然后**结束**。

而你要的是：**答案给完，系统才刚刚开始工作。**

## 2. 现状（as-is）与目标（to-be）

**现在你的一天：**

```
做纸质卷子 → 错了 → (想抄到错题本 / 懒得抄) → 卷子塞进一摞
                                    ↓
遇到不会的 → 问 AI → 拿到答案 → 懂了 → 关掉 → 三天后忘了
                                    ↓
考前 → 翻那摞卷子 → 找不到 → 只能从头再看一遍
```

三个断点：**痕迹不落库、落库不关联、关联不复发**。

**目标状态（to-be）：**

```
拍照/扫描 ─┐
网页/PDF ──┼→ 结构化(题目/选项/答案/公式) ─┐
对话提问 ──┘                                  ↓
                              知识点标注 + 先修关联
                                          ↓
                          FSRS 排程 → 每日「今天该练这 10 分钟」
                                          ↓
                          你做 → 判对错 → 掌握度变了 → 明天队列重算
                                          ↓
                          周报：哪个知识点在退步、哪个错因在重犯
```

闭环的关键是**最后一步会回头改第一步的优先级**。没有回头，就只是个笔记本。

## 3. 三个使用节奏（这是硬约束，不是场景描述）

单个用户的产品，功能再多也只在三种时刻被打开。它们直接决定界面结构：

| 节奏 | 时长 | 在哪 | 要干什么 | 界面要求 |
|---|---|---|---|---|
| **碎片** | 1–3 分钟 | 课间、通勤、睡前 | 看今天该复习的、拍两张照、问一句 | 首屏必须是**「今天该干什么」的单一动作**，不是功能九宫格 |
| **专注** | 20–40 分钟 | 晚上书桌 | 批量录入、整理错题、做变式、看图谱 | 批量操作、键盘友好、可中断续做 |
| **冲刺** | 1–2 小时 | 考前 | 按知识点拉清单、错题重做、薄弱专项 | 全屏列表 + 强筛选 + 计时/连做模式 |

> **由此定下一条设计铁律**：功能入口全部下沉，首屏**只给她和你的一句话**。
>
> **修订（2026-11-14）**：初版写的是「首页 = 今日队列」，那是**工具类 App** 的默认形态。既然定位是「一个会主动找你的伙伴」，首屏必须是**对话流**——今日队列降级为**她今早的第一条消息**（`review_card`）。同一件事，形态从"页面"变成"她说的话"。完整设计见 **[07-产品设计-单一会话.md](07-产品设计-单一会话.md)**。仍然成立的是：**任何「首页功能宫格」的方案都是错的**。

## 4. 功能需求

优先级：**P0 = 没有它闭环不成立**；P1 = 显著提升但可后补；P2 = 锦上添花。

### 4.1 采集（Capture）

| 优先级 | 需求 | 验收标准 |
|---|---|---|
| **P0** | 批量拍照录入：一次拍一组，后台排队识别，可离开页面 | 拍 10 页 ≤ 60 秒完成拍摄；识别在后台跑，失败可重试，不阻塞 |
| **P0** | 相册/系统分享导入（分享菜单直接进 App） | 从微信/相册分享一张图能进 App |
| **P0** | 文本/对话导入：把「问 AI 的那段」贴进来即入库 | 粘贴 → 自动抽知识点 → 生成待复习条目 |
| P1 | PDF / 网页剪藏 | 给定 URL 或 PDF 能抽出正文与题目 |
| P1 | 手写答案区单独识别（答案与题目对齐） | 答案错位率 < 10% |
| P2 | 语音口述录入（"这题我错在没考虑重力"） | 转写后落到错因备注 |

> **真正的瓶颈在「录入的前 3 秒」。** 一页纸如果要点 5 次、填 3 个框，你就不会用第二次。P0 的采集必须是：**拍 → 什么都不填 → 返回**。所有归类都能事后补，或由 AI 预填。

### 4.2 结构化（Structure）

| 优先级 | 需求 | 验收标准 |
|---|---|---|
| **P0** | 题目切分：一页纸 → 一道一道独立题目 | 单页切题准确率 ≥ 90%（印刷体、标准试卷版面） |
| **P0** | 字段抽取：题干、选项、答案、解析、分值 | 五个字段至少四个正确，且置信度可见 |
| **P0** | 数学公式转 LaTeX 并可渲染 | 分数/根号/上下标/积分不错；不可编译时有降级 |
| **P0** | 知识点自动标注（一题可挂多个，有权重） | 主知识点命中率 ≥ 80%，可手工改 |
| P1 | 错因分类（概念不清 / 计算错 / 读题错 / 粗心） | 可由你做一次单选修正并记住规律 |
| P1 | 题干去重（同一题在练习册和试卷上都出现） | 相似度 > 0.92 自动合并，保留多来源 |
| P2 | 变式题生成（同知识点、换数字/换情境） | 生成后需你确认才入库 |

> **必须有人工复核队列。** OCR/VLM 置信度低于阈值的进「待确认」，你滑一下就能过。**完全无人值守的自动入库，错一次就会污染整个知识图谱**——这是这类系统最常见的死法。

### 4.3 知识体系（Knowledge）

| 优先级 | 需求 | 验收标准 |
|---|---|---|
| **P0** | 知识点树：学科 → 章 → 节 → 知识点（可无限层级） | 可从现成课标数据导入（见 03，数学已有 1644 个知识点 + 2403 条先修边） |
| **P0** | 先修边（A 是 B 的前置） | 支持增删、可见「学 B 之前该会 A」 |
| **P0** | 题目 ↔ 知识点 多对多 + 主知识点标记 | 一道题可挂 1 主 + N 辅 |
| P1 | 掌握度：节点颜色 = 掌握度（由卡片 S/D 聚合） | 掌握度变化有历史曲线 |
| P1 | 图谱视图：可聚焦某知识点，看上下游 + 相关题目 | 节点 > 300 时仍可用（需聚合/折叠） |
| P2 | 跨学科边（物理的「函数图像」关联数学的「二次函数」） | 手工维护为主 |

### 4.4 复习（Review）—— 产品的引擎

| 优先级 | 需求 | 验收标准 |
|---|---|---|
| **P0** | FSRS 卡片调度（四档评分：again/hard/good/easy） | 用现成库（py-fsrs / ts-fsrs），不自研算法 |
| **P0** | 每日队列：到期的卡 + 到期未重做的错题 | 打开即给，数量可配（默认 10–20） |
| **P0** | 复习记录全量留痕（revlog），能反算与训练参数 | 每次评分都落一条 log，永不覆盖 |
| P1 | 知识点级调度：先修未达标时，后继卡片降权或冻结 | 「先修闸门」开关，默认开 |
| P1 | 错题重做模式：遮住答案，写完拍照或自评 | 重做记录独立于首次错题 |
| P1 | 参数优化：用你的 revlog 训练个人 FSRS 权重 | 数据 ≥ 1000 条复习后可跑 |
| P2 | 变式训练：同知识点不同题 | 从库里抽，不够才生成 |

### 4.5 提问（Ask）—— 差异化所在

| 优先级 | 需求 | 验收标准 |
|---|---|---|
| **P0** | 对话式问答，能带上下文（这次问的和上次问的有关） | 多轮 + 引用历史笔记 |
| **P0** | **回答后自动「沉淀」**：抽 1–3 个卡点知识点 → 问你「要不要加进复习？」（默认已加，可撤销） | 一次问答 ≤ 3 秒生成沉淀条目，不打断阅读 |
| **P0** | 引用溯源：答案里提到的你的旧笔记/旧错题可点回原文 | 每条引用可跳转 |
| P1 | 回答分级：先给「提示」再给「详解」（苏格拉底式，不要一上来给答案） | 二级展开，默认折叠详解 |
| P1 | 追问记录合并成一条「学习事件」 | 一次会话 = 一个事件，可回看 |
| P2 | 拍照问：对着题直接问 | 复用采集管线 |

> 用户诉求第 5 条的落点全在这一节。**「AI 只给答案」的解法不是换更强的模型，是让答案流进数据库。** 技术上是：问答结束后跑一次结构化抽取（不占你阅读时间，异步），产出 `kp_id + 错因 + 你的原话片段`。

### 4.6 检索（Recall）—— 「我以前做过这题」

| 优先级 | 需求 | 验收标准 |
|---|---|---|
| **P0** | 关键词 + 知识点 + 时间 + 错因 组合筛选 | 三条件组合 ≤ 200ms 返回 |
| **P0** | 语义搜索（模糊描述能搜到） | 「我错过的带弹簧的题」能召回 |
| P1 | 以图搜题（拍一张旧题找原题） | Top-3 命中率 ≥ 85% |
| P1 | 相似题推荐（同一知识点的其它题） | 向量召回 + 同知识点加权 |

### 4.7 主动关怀（Proactive）—— 「时时关心我」

| 优先级 | 需求 | 验收标准 |
|---|---|---|
| **P0** | 每日推送：今天该复习几张、昨天错了几道（一条，不长） | 可设时间窗，可静音 |
| **P0** | 周报：本周新增/复习量、掌握度变化 Top3 上升 & 下降、重犯错因 | 每周日自动生成，可在 App 看历史 |
| P1 | 遗忘预警：「『楞次定律』你 21 天没碰了，掌握度掉到 0.42」 | 只对高价值知识点预警，避免噪音 |
| P1 | 连续未学提醒（断签第 3 天提醒一次，之后不再骚扰） | 频率上限硬编码，防打扰 |
| P2 | 学习计划：给定考试日期，反推每日配额 | 可手工覆盖 |

> **「主动」的边界要一开始就定死**：一天最多 2 条推送；任何推送必须可一键「今天别烦我」；不做游戏化打卡弹窗。你要的是关心，不是催收。

### 4.8 统计（Insight）

| 优先级 | 需求 |
|---|---|
| **P0** | 知识点掌握度热力图（按章节） |
| P1 | 错因分布饼图、重犯率曲线、学习时长（按科目/周） |
| P2 | 预测：按当前进度，某知识点在考试日前能否达标 |

## 5. 非功能需求

| 维度 | 要求 | 为什么 |
|---|---|---|
| **用户规模** | 单用户（你自己），最多加 1–2 个家人 | 决定了**不做多租户、不做权限体系、不做计费**。所有表都可以只有 `user_id=1` 一列甚至不要 |
| **数据主权** | 全部数据可一键导出为开放格式（Markdown + JSON + SQLite 文件 + Anki apkg） | 「永久项目」的底线：**App 可以死，数据不能死** |
| **离线** | 复习队列、错题浏览、笔记阅读可离线；录入可离线排队 | 地铁/教室信号差是常态 |
| **延迟** | 首屏 < 800ms；问答首 token < 2s；录入识别异步不阻塞 | 碎片场景容忍度极低 |
| **成本** | 服务器 ≤ ¥10/月，模型 ≤ ¥50/月 | 见 05；超出太多会让人想关掉它 |
| **隐私** | 数据只在自己服务器；模型调用可切本地/国内 API；不外传图片 | 学习数据比聊天记录更敏感 |
| **可维护** | 单人能在**一个周末**内完成一次依赖升级；任意模块可单独替换 | 「可持续可维护」的具体含义 |
| **可恢复** | 每日自动备份 + 每月一次恢复演练 | 没有演练的备份等于没有备份 |

## 6. 明确不做（Scope Boundary）

写清楚不做什么，比写做什么更能保住工期：

1. **不做多用户/班级/分享**。这是你自己的本子。想做班级版是另一个产品（而且你已有 ClassTool 那条线）。
2. **不做题库市场/卖课/社交**。
3. **不做游戏化**（积分、徽章、排行榜）。对单用户无效，且会稀释「复习」这个核心动作。
4. **不自研间隔重复算法**。FSRS 已经赢了，直接用库。
5. **不自研 OCR 模型**。用 PaddleOCR / VLM，做的是流水线编排，不是模型训练。
6. **不做全学科一次性铺开**。先 1 个学科跑通闭环（建议数学，因为公式链路最难，跑通了别的都简单；或选你当下最痛的那科）。
7. **不做 Web 端**（第一年）。Android + 一个只读的 Web 看板（周报）就够。
8. **不上 Google Play**。自用 + GitHub Releases 分发，绕开 targetSdk 与开发者验证的坑（见 04）。

## 7. 三个必须先拍板的设计决策

### 决策 A：Pi 就是 AI 运行时（已按你的判断更正）

> **修订（2026-11-14）**：本节初版写的是「Pi 只做对话大脑」，**把 Pi 写窄了，已按你的意见更正**。详见 [06-AI运行时与工具设计.md](06-AI运行时与工具设计.md)。

你的判断成立，而且理由比我初版更硬：

- **对话循环别自己写**：流式、tool_call 解析与执行、多轮、中止、steer/followUp、上下文 compaction——这是最容易写崩的一千多行，Pi 已经写好了。
- **provider 也别自己收集**：Pi 自带 **bundled catalog + pi.dev 远程覆盖**，含 provider、model ID、能力、上下文长度、价格；`pi update --models` 刷新，离线有缓存。任何 OpenAI/Anthropic 兼容端点（含中转、Ollama、vLLM）只要在 `models.json` 写 `baseUrl` + `api` 三个字段。**「自己收集各家信息」这件事直接从项目里消失。**
- **连成本和限流都帮你省了**：`promptCache` 声明缓存寿命触发 cache warming（长系统提示的输入价能低到 1/10 量级）、`inputLimits.images.resize` 把题目照片压到 1568px/512KB、`modelOverrides` 改元数据。

**所以分工是：**

| 你写什么 | 内容 |
|---|---|
| **① 界面** | Android（Compose + M3），含今日队列 / 采集 / 图谱 / 错题 / 统计 |
| **② 工具** | 让 agent 能读写学习库的一组 tool（`kp_search`、`question_search`、`deposit_from_chat` …，共 ~20 个，分读写、带权限闸门） |
| **③ 确定性服务** | FSRS 调度、知识点图、错题、统计、API——这些**本来就不该交给 LLM** |
| **④ 薄网关** | ~200 行 SSE 转发 + 鉴权。**是传输层，不是 AI 层**（Pi 无 server 模式，手机直连不了） |

**你不需要再写**：provider 适配、模型清单、定价表、对话循环、流式解析、工具调用协议、重试、上下文裁剪、会话存储、密钥管理、token 核算。**这十条从原计划里删掉——这是项目能做完的前提。**

> 我初版把「Pi 无内置记忆」列为风险，在你的场景里**这个判断是错的**：你的记忆在 PostgreSQL，通过工具暴露给 Pi。**"Pi 需要记忆"是个伪需求——你的工具就是它的记忆。** 见 06 §4。

### 决策 B：知识图谱不上图数据库

用 PostgreSQL 两张表（`kp` 节点 + `kp_edge` 边）就够。理由：
- 你的图规模是**千级节点、万级边**，PG 的递归 CTE 完全打得过；
- Neo4j 要多一个 JVM 服务、多一套备份、多学一门 Cypher——单用户项目不值得；
- 「图谱」对用户是**一个视图**，不是一种存储。存边表、画图时现算即可。

### 决策 C：先闭环，再智能

第一版宁可「AI 笨一点」也要把 **拍 → 存 → 排 → 复习 → 统计** 这条链路跑通。理由：这条链路不依赖任何模型能力，是纯工程；而它是你每天真正会用的部分。AI 只在「结构化」和「问答沉淀」两处出现，且都可以先用手工/半自动替代。

## 8. 成功判据（三个月后回看）

不设 KPI 的项目会烂尾。用你自己能验证的四条：

| # | 判据 | 目标 |
|---|---|---|
| 1 | **录入摩擦**：一页纸从拍照到入库（含确认） | ≤ 20 秒，且可以完全不填表 |
| 2 | **日用率**：有复习任务的日子，你真的打开了 App | ≥ 60% |
| 3 | **重犯率**：同一知识点错第二次的比例 | 三个月后比第一个月**下降**（哪怕只降 10%） |
| 4 | **数据不丢**：随机抽 1 天的备份，能完整恢复到另一台机器 | 100% 成功 |

第 3 条如果不动，说明「关联 + 调度」没做对，要回头改算法而不是加功能。
