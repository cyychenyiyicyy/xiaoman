## 1. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│  Android App（Kotlin + Compose + M3）                          │
│  首页=今日队列  采集=拍照/分享/粘贴   二级=图谱/错题/统计        │
│  离线：Room 缓存 + outbox 队列 ｜ 推送：ntfy + WebSocket        │
└───────────────┬──────────────────────────────────────────────┘
                │ HTTPS  REST/JSON  (OpenAPI 生成客户端)
┌───────────────▼──────────────────────────────────────────────┐
│  API 服务（FastAPI + Python 3.11+）                            │
│  ├ auth        单用户 Token                                   │
│  ├ capture     上传/任务队列/状态轮询                          │
│  ├ review      FSRS 调度 + 队列生成  ← 核心                    │
│  ├ knowledge   知识点树 / 先修边 / 掌握度聚合                   │
│  ├ search      关键词 + 向量 + 图 三路召回                     │
│  ├ chat        → 网关 → Pi（AI 层本体：循环/provider/会话）   │
│  └ stats       周报/热力图/重犯率                              │
└───────┬───────────────────┬──────────────────┬───────────────┘
        │                   │                  │
┌───────▼──────┐  ┌─────────▼────────┐  ┌──────▼──────────────┐
│ PostgreSQL 18│  │ 结构化 worker     │  │ Pi agent runtime     │
│ + pgvector   │  │ (Python, 独立进程) │  │ (Node 22, TS SDK)   │
│ 关系+向量+全文│  │ OCR→切题→公式→组装 │  │ 循环/provider/会话    │
└──────────────┘  └─────────┬────────┘  └─────────────────────┘
                            │ 调
                    ┌───────▼────────┐
                    │ OCR 服务        │
                    │ PaddleOCR 或云API│
                    └────────────────┘
```

**四个进程，三种语言**，看起来多，但每个都有明确的「可单独替换」边界：

| 进程 | 语言 | 挂了会怎样 | 换掉成本 |
|---|---|---|---|
| API 服务 | Python | 全站不可用 | 高（核心） |
| 结构化 worker | Python | 录入积压，不影响复习 | **低**（纯函数式，可换） |
| Pi runtime | Node/TS | 问答不可用，其余正常 | 低（**AI 层本体**，但接口面只有 4 个 API，见 06 §8） |
| PostgreSQL | — | 全站不可用 | 高（但备份简单） |

> 这个切法的意义：**你未来 3 年最可能换的是 OCR 和 LLM，最不可能换的是数据库和调度逻辑。** 所以把前两者隔离成可替换进程，把后两者做扎实。

## 2. 技术栈决定表

| 层 | 选择 | 一句话理由 | 备选与为何不选 |
|---|---|---|---|
| **Android** | **Kotlin + Jetpack Compose + Material3** | 官方路线、APK 最小（~2.9MB vs Flutter 16MB）、CI 最成熟、依赖有官方长期承诺 | Flutter（唯一强项是 iOS，但你现在不需要）；RN/Expo（生态杂、版本碎片）；KMP（**现在上就是过度设计**） |
| **本地存储** | **Room 2.8.5**（别用还在 alpha 的 Room 3.0） | 单平台用官方方案 | SQLDelight（KMP 场景才需要） |
| **网络** | **Ktor Client + kotlinx.serialization** | Kotlin 原生、支持 WebSocket | Retrofit（也可，但 Ktor 一体化更省） |
| **后端** | **Python 3.11+ / FastAPI 0.162.x + SQLAlchemy 2 + Pydantic v2** | 一人写最快、AI 生态最好、自动出 OpenAPI 供 Android 生成客户端 | NestJS（样板多）；Go（开发慢、LLM 生态弱） |
| **数据库** | **PostgreSQL 18 + pgvector 0.8.7** | 关系 + 向量 + 全文一个 ACID 引擎，一个容器 | SQLite+sqlite-vec（数据量小也行，但服务端别两套）；**Neo4j 不推荐**（多一个 JVM 服务/备份/Cypher，收益为零） |
| **任务调度** | **APScheduler（进程内）+ cron/systemd timer** | 单用户不配消息队列 | Celery/arq/BullMQ 都要 Redis，纯负担 |
| **鉴权** | **Tailscale（个人免费，6 用户）+ 兜底 Caddy Basic Auth + API Key** | 服务器 443 可对公网全关，最省事也最安全 | Cloudflare Access（原生 App 要 OAuth/PKCE，负担重）；Passkey（单用户不值得） |
| **部署** | **Docker Compose + Caddy** | Caddy 自动签发/续期证书，零 cron | Nginx+certbot（多一套手写配置和续期） |
| **推送** | **自建 ntfy**（应用外）+ **WebSocket 长连接**（应用内） | FCM 国内不可用；OneSignal 免费档已缩到 1000 MAU 且仍依赖 FCM | Gotify（生态小）；MQTT（要双向控制才用） |
| **监控** | **Uptime Kuma**（主动探活）+ **healthchecks.io**（盯 cron） | 分工明确：一个轮询服务、一个等 cron 报到 | Prometheus（太重） |
| **分发** | **GitHub Releases 主 + F-Droid 副（长期）** | F-Droid 审核常超一个月，不能当发布通道 | Google Play（国内用不到，且 targetSdk 必须 ≥36） |

### 2.1 三条 2026 年的硬约束（容易踩）

1. **Google Play 新应用必须 target API 36**（2026-08-31 起）。GitHub/F-Droid 分发不受限 —— **你不必为此升级，但要知道**。
2. **Android 开发者验证**：2026-09-30 起在巴西/印尼/新加坡/泰国等地区开始拦截未验证开发者的安装，**全球目标 2027**。→ **建议现在去注册开发者身份并占住 `site.e1e.study`**，否则将来可能装不上自己的 APK。
3. **F-Droid 元数据只认 `.yml`**（`.txt`/`fastdroid.json` 已于 2020 移除）。且它自己从源码构建——**依赖必须全 FOSS**，Firebase/GMS 是硬拒绝项。

### 2.2 MD3 的三个具体坑

- **`material3` 1.4.0 是当前 stable，Material 3 Expressive 在 1.5.0** —— 想要 Expressive 得等 stable，别用 beta 上生产。
- **Android 16 QPR2 强制主题化图标，App 不能 opt out** → **必须提供 adaptive icon 的 `monochrome` 图层**，否则被系统自动染色，很丑。
- **Android 16 QPR2 还带来强制暗色模式**（对不原生支持暗色的 App 生效）→ **暗色必须做对**。

动态取色的正确写法（库内部已做 API 31+ 判断与低版本回退，不用自己写）：

```kotlin
@Composable
fun AppTheme(darkTheme: Boolean = isSystemInDarkTheme(), content: @Composable () -> Unit) {
    val ctx = LocalContext.current
    val scheme = if (darkTheme) dynamicDarkColorScheme(ctx) else dynamicLightColorScheme(ctx)
    MaterialTheme(colorScheme = scheme, typography = M3Typography, content = content)
}
```

## 3. Pi 框架：它就是 AI 层本体

> **修订（2026-11-14）**：本节原结论是「Pi 只做对话大脑，不做系统内核」，**写窄了，已更正**。
> 准确口径：**Pi 承担全部 AI 底层**（对话循环 / provider / 模型目录 / 会话 / compaction / 成本），你写界面 + 工具 + 一个薄网关。
> 设计与工具清单移到 **[06-AI运行时与工具设计.md](06-AI运行时与工具设计.md)**，本节只保留选型所需的客观事实。

### 3.1 事实

| 项 | 值 |
|---|---|
| 仓库 | `earendil-works/pi`（原 `badlogic/pi-mono`），MIT |
| 版本 | v1.5.2（2026-11-10），npm `@earendil-works/pi-coding-agent`，需 **Node ≥ 22.19** |
| 定位 | **极简 agent harness**，终端优先，内核 <1000 token，**无子 agent、无计划模式、无权限弹窗** |
| 模型 | 15+ provider 数百模型；兼容 Anthropic/OpenAI 协议；**直连 llama.cpp（GGUF）**，Ollama/vLLM 走 `openai-completions` 端点 |
| 工具 | 内置 `read/bash/powershell/edit/write/grep/find/ls`（默认只启前四） |
| 上下文 | compaction（reserveTokens 16384 / keepRecentTokens 20000）、会话是 **append-only JSONL 树**、`/tree` `/fork` `/clone` 不丢历史 |
| 记忆 | **无内建长期 memory**（只有 `AGENTS.md`/`CLAUDE.md` 之类指令文件）。**对本项目无影响**：你的学习数据在 PostgreSQL，通过工具暴露给 Pi，见 06 §4 |
| 模型目录 | **自带 bundled catalog + pi.dev 远程覆盖**：provider、model ID、能力、上下文长度、价格；离线有缓存，`pi update --models` 刷新 |
| 成本控制 | `promptCache` 声明缓存寿命（触发 cache warming）、`inputLimits.images.resize` 压图、`modelOverrides` 改元数据 |
| 扩展 | `pi install npm:|git:|本地路径`，一个 package 可含 `extensions/ skills/ prompts/ themes/` |
| 嵌入 | **SDK（进程内）** / **RPC mode（stdio JSONL）** / JSON event stream / print mode |
| 持久化 | 本地 JSONL，默认 `~/.pi/agent/sessions/`，可换 `sessionDir` |

### 3.2 三个必须知道的风险（都不是「别用 Pi」，是「用的时候注意」）

1. **迭代极快、破坏性变更多**：1.0.0（10-01）→ 1.5.2（11-10）约 6 周发 8 个 minor。0.87 删了 `shouldStopAfterTurn`；1.2.0 改了 `before_agent_start` 事件形状；1.5.0 把工具参数校验从 TypeBox 换成 `pi-schema`；1.5.1 改了 `GrepOperations.readFile`。→ **必须锁精确版本，绝不跟 latest。**
2. **没有官方 server 模式**：`pi-server` / `pi-client`（npm 停在 1.1.0）已被 1.2.0 changelog 明确移除。→ **手机不能直连 Pi**，中间要架一层网关。**注意：这层是传输层（SSE 转发 + 鉴权），约 200–300 行，不是 AI 底层**，见 06 §3。
3. **无权限系统、无沙箱**：工具以进程权限执行。服务器部署必须：专用低权用户 / 容器隔离 / 收紧 `defaultTools`（可只留 `read` + 你的自定义查询工具）+ 设 `defaultProjectTrust`。

### 3.3 接法（定稿）

```
Android App
   │ HTTPS / SSE
   ▼
FastAPI（业务：复习调度 / 知识图谱 / 错题 / 统计 / 鉴权）
   │ HTTP（内网）
   ▼
网关（Node/TS，~200 行）：createAgentSession → subscribe → 转发事件
   │ 进程内调用
   ▼
Pi（AI 层本体：对话循环 / provider / catalog / 会话 / compaction / 成本）
   │ 工具回调
   ▼
你的学习领域工具（kp_search / question_search / deposit_from_chat …）
   │ HTTP
   ▼
FastAPI → PostgreSQL
```

- **不要**用 print mode 做主线（无流式、无连续会话）；
- **不要**用 RPC mode 直连手机（stdio 传输，手机连不上）；
- **要**单独一个 Node 服务常驻跑 Pi，暴露 `/agent/chat`（SSE）与 `/agent/entries`。**网关只做转发，不做任何 AI 逻辑。**

**会话映射**：1 个**学习主题/学科** = 1 个 Pi session（长期存在，compaction 才有意义）；每次提问 = 一次 `prompt`。增量同步用 `get_entries(since: entryId)` —— entry id 是持久游标，手机断线重连只取新增。**单 session 同时只能有一个活跃 run**，流式中再发消息必须带 `streamingBehavior: "steer" | "followUp"`。

**领域知识打包**：做成 Pi package，`pi install git:<你的仓库>` 部署（含 skills/prompts/extensions）。skills 按 description 惰性加载，控制 prompt 体积。工具超过约 15 个时启用内置 `tool-search` 扩展。

> 完整的工具清单、`models.json`、权限闸门、一天的验证步骤 → **[06](06-AI运行时与工具设计.md)**。

### 3.4 如果你其实指的是 Pydantic AI

判断依据：出现「终端 / SDK / RPC / packages / 扩展」→ 是 pi.dev 的 Pi；出现「Python / 类型安全 / Logfire / durable」→ 是 **Pydantic AI**。

**若你指的是 Pydantic AI，架构完全不用改**：把上图里的「Pi runtime」换成一个 FastAPI 内部的 `pydantic_ai.Agent`，反而更省一个进程。**所以这条不确定性不影响架构决策**——这是好消息。

> 顺带排除：「Personal Intelligence (PI)」是学术概念（Zenodo 论文 2026-01），不是可依赖的代码框架；「Physical Intelligence (π)」是机器人公司；`pi-ai-python` 是第三方 Python 移植、落后上游约 2 个 minor，别用。

## 4. API 设计

**REST + OpenAPI**，不用 GraphQL/tRPC。理由：客户端是 Kotlin（tRPC 用不上）；单人 App 没有「多客户端要不同数据切片」的需求（GraphQL 的场景）；FastAPI 自动出 `/openapi.json`，Android 端可生成 Kotlin 数据类，**类型不用手抄**。

### 4.1 资源清单

```
POST   /api/v1/capture/pages            上传一页（multipart），返回 task_id
GET    /api/v1/capture/tasks/{id}       轮询识别状态 queued|running|done|failed
POST   /api/v1/capture/tasks/{id}/retry 重试

GET    /api/v1/questions                列表：?kp=&error_type=&from=&to=&q=&limit=&cursor=
POST   /api/v1/questions                手工新建
PATCH  /api/v1/questions/{id}           改题干/答案/知识点
POST   /api/v1/questions/{id}/search-similar   以图搜题 / 相似题

GET    /api/v1/kp/tree?subject=math     知识点树（一次拉全，缓存）
GET    /api/v1/kp/{id}/neighbors        上下游 + 相关题目
GET    /api/v1/kp/{id}/mastery-history  掌握度曲线
POST   /api/v1/kp/{id}/edges            加先修边（环检测）

GET    /api/v1/review/queue?limit=20    今日队列（核心接口）
POST   /api/v1/review/{card_id}/grade   body: {rating:1..4, duration_ms}
POST   /api/v1/mistakes/{id}/attempt    重做记录

POST   /api/v1/chat                     发送（SSE 流式返回）
GET    /api/v1/chat/{session}/entries?since=<entryId>   增量拉取
POST   /api/v1/chat/{session}/deposit   把本轮沉淀为复习条目（可撤销）

GET    /api/v1/stats/weekly             周报
GET    /api/v1/stats/heatmap?subject=   热力图

GET    /api/v1/export/apkg              导出 Anki apkg（兜底，必须有）
POST   /api/v1/export/full              导出全量 JSON + Markdown zip
```

### 4.2 三条约定

1. **所有列表用 cursor 分页**（不用 offset），因为你要按时间往回翻，且会边写边读。
2. **所有写操作幂等**：客户端生成 `op_id`（UUID），服务端去重。这是离线 outbox 的前提。
3. **`/review/queue` 必须是纯函数输出**：给定 `now + 用户配置 + 当前掌握度`，输出确定的队列。**不要在里面塞 LLM 调用**——队列生成慢 3 秒，你就不会打开 App 了。

## 5. Android 端结构

```
app/
 ├ ui/           Compose 页面（今日 / 复习 / 采集 / 图谱 / 错题 / 统计 / 设置）
 ├ domain/       纯 Kotlin，无 Android 依赖 ← 将来要 iOS 就靠这层搬
 ├ data/
 │   ├ remote/   Ktor Client + OpenAPI 生成的 DTO
 │   ├ local/    Room（卡片、队列、题目缓存、outbox）
 │   └ repo/     仓库层：远端写回 Room，UI 只 observe Room
 └ work/        WorkManager：定时同步（最短 15 分钟）+ 上传重试
```

### 5.1 离线优先的三条铁律

1. **网络层永远不直接喂 UI**：写入一律先落 Room，UI 观察 Room（Flow），网络只负责把远端变化写回 Room。
2. **本地 outbox 表 + 幂等 op_id + 服务端 last-write-wins**：比强行做通用同步引擎省事一个数量级。
3. **复习可以完全离线**：队列在本地算不出来？可以——**每次同步时把未来 3 天的队列预下发**，本地只按 rating 记录，联网时回放 revlog。这是最省钱的做法（服务器不用实时服务你）。

### 5.2 首屏

```
┌─────────────────────────┐
│ 今天 · 11月14日          │
│                         │
│   ○ 12 张待复习          │  ← 主按钮，一按就进
│   ○ 3 道错题待重做       │
│                         │
│ 继续上次：磁场对电流…     │  ← 次级
│                         │
│ ＋ 拍一页                │  ← FAB，最快入口
└─────────────────────────┘
```

**只有一个数字是大的**。任何「功能九宫格」都违背碎片场景。

## 6. 部署与持续集成

### 6.1 docker-compose 骨架

```yaml
services:
  db:
    image: pgvector/pgvector:pg18
    volumes: ["pgdata:/var/lib/postgresql/data"]
  api:
    build: ./server
    environment: { DATABASE_URL: "postgres://...", PI_GATEWAY: "http://pi:8787" }
    depends_on: [db]
  worker:
    build: ./server
    command: python -m worker
    depends_on: [db]
  pi:
    build: ./agent
    environment: { NODE_VERSION: "22.19" }
  caddy:
    image: caddy:2-alpine
    ports: ["443:443", "80:80"]
    volumes: ["./Caddyfile:/etc/caddy/Caddyfile", "caddy_data:/data"]
volumes: { pgdata:, caddy_data: }
```

Caddyfile 三行：

```
study.e1e.site {
  reverse_proxy api:8000
  basicauth { * } <bcrypt>
}
```

**备份**：`pg_dump` + 异地对象存储，cron 跑，配 healthchecks.io 心跳。**每月做一次恢复演练**——没有演练的备份等于没有备份。

### 6.2 GitHub Actions（Android）

```yaml
name: android
on:
  push: { tags: ['v*'] }
  workflow_dispatch:
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '21' }
      - uses: gradle/actions/setup-gradle@v5      # v5 有增强缓存，公开仓库免费
      - run: echo "${{ secrets.KEYSTORE_BASE64 }}" | base64 -d > $RUNNER_TEMP/release.keystore
      - run: |
          ./gradlew assembleRelease \
            -Pandroid.injected.signing.store.file=$RUNNER_TEMP/release.keystore \
            -Pandroid.injected.signing.store.password=${{ secrets.KEYSTORE_PASSWORD }} \
            -Pandroid.injected.signing.key.alias=${{ secrets.KEY_ALIAS }} \
            -Pandroid.injected.signing.key.password=${{ secrets.KEY_PASSWORD }}
      - uses: actions/upload-artifact@v4
        with: { path: app/build/outputs/apk/release/*.apk, retention-days: 7 }
      - uses: softprops/action-gh-release@v3    # v2 已停止维护，新项目用 v3
        with: { files: app/build/outputs/apk/release/*.apk }
```

**要点**：
- 用 `-Pandroid.injected.signing.*` **注入签名，不改 build.gradle**，密码不进仓库；
- **不要用 `assembleDebug` 发布**，也不要 `run_number` 造版本号；
- **`versionCode` 必须全局单调递增**（F-Droid 硬要求），用 **git tag 驱动**：`v1.5.0` → name `1.5.0`、code `10500`；
- **keystore 离线多备份**：丢了就无法给已安装用户发更新；
- **artifact `retention-days: 7`**：免费额度 500MB 与 Packages 共享，别每次留 90 天。

## 7. 仓库结构（monorepo）

```
study-agent/
 ├ server/          FastAPI（api + worker + 迁移 + 测试）
 ├ agent/           Pi runtime（Node/TS）+ 学习领域 package
 ├ android/         Compose 工程
 ├ docs/            ARCHITECTURE.md / DECISIONS.md(ADR) / API.md

```

**为什么 monorepo**：单人项目，跨端改一个数据结构要一次提三个仓库太痛。**代价**是要配好路径过滤的 CI（`paths: ['android/**']`），否则每次改文档也触发打包。

## 8. 关键取舍备查

| 问题 | 我的建议 | 若你坚持另一种 |
|---|---|---|
| 用 Pi 还是 Pydantic AI | **用 Pi**：AI 底层全交给它，你只写工具 + 薄网关（06） | Pydantic AI 只有在「后端想全 Python」时才更顺，工具层要换个写法 |
| 知识图谱要不要 Neo4j | **不要**，PG 边表 + 递归 CTE | 真要上，等节点过万再说 |
| 要不要用思源/Logseq 当底座 | **不要**，自建 8 张表 | 若已有大量思源笔记 → 只做只读同步 |
| Web 端要不要做 | **第一年不做**，只做一个只读周报页 | 做的话别用 `@material/web`（已进维护态），用 petal-elements 或手写 CSS 变量 |
| 要不要上 Play | **不上** | 上的话 targetSdk 必须 ≥36 + $25 账号 |
| 离线怎么同步 | **Room + outbox + 幂等 op_id** | 别做通用同步引擎/CRDT，那是给多端编辑器的 |
