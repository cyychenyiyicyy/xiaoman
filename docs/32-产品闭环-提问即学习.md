# 32 · 产品闭环：提问即学习

> 一句话：**她负责记住，你只负责问。**
>
> 这篇不讲界面细节，只讲清楚「个人学习助理」到底是什么、数据怎么转起来、先做哪一段。
> 相关：`docs/01`（为什么做）、`docs/07`（单一会话）、`docs/10`（错题）、`docs/22`（记忆）、`docs/30`（题库解析）、`docs/31`（地图）。

---

## 1. 定位：不是答题工具，是"会记住你的老师"

市面上的产品都是**一次性的**：你问，它答，结束。
小满的不同只有一句话：

> **答案给完，档案才开始增长。**

- 你问「钠和水为什么反应这么剧烈」→ 她不仅答，还记下**这个点你还没懂**；
- 你问「这题怎么做」→ 她答完，**这道题自动进错题本**，明天用变式再问你；
- 你连续两次在同一个点上卡住 → 她下次开口先说**「先退回先修的那个点」**。

所以这个产品真正的资产不是模型、不是题库大小，而是**一份越用越准的学习档案**。

---

## 2. 核心洞察：提问本身就是最好的采集

> 你只有不会的时候才去问。

这句话是整个产品的地基。每一次提问都暴露了一个薄弱点，比任何"手动标记"都真实：

| 你做的动作 | 暴露了什么 |
|---|---|
| 问一个知识点「为什么/是什么」 | 这个点你没把握（弱信号，可能只是好奇） |
| 贴一道题问「怎么做」 | 这道题你不会（强信号） |
| 拍照一整页卷子 | 这一页里有你需要处理的题（中信号） |
| 复习时评「忘了 / 模糊」 | 这个点确实没掌握（强信号） |
| 说「这个我会，别记了」 | 反向证据，要能撤 |

**关键克制**：不能"见问就标红"。问概念、确认、拓展都算"在学"，不等于"不会"。
产品要有一条**证据分级**规则（§5），否则错题本会被噪音灌满，你就不信它了。

---

## 3. 档案的三层对象

整个系统只围绕三个东西转，其它都是视图：

| 层 | 对象 | 回答的问题 | 数据 |
|---|---|---|---|
| **点** | 知识点 `kp` | 这个点她懂不懂？ | 掌握度 + 证据（问过/错过/复习评分）+ 先修边 |
| **题** | 题目 `question` | 这道题她会不会？ | 答案/解析/知识点/难度 + 错次 + 错因 + 我的原话 |
| **事** | 事件 `event` | 她当时是怎么问的？为什么问？ | 一轮对话的原话片段、时间、学科 |

- **点**决定「她该学什么」，**题**决定「她该练什么」，**事**决定「她下次怎么开口」。
- 三者不是三份数据，是**同一份档案的三个切面**：题挂到点上，事件解释题和点的来由。
- 题库、地图、错题本、复习队列，都只是这份档案的**透镜**，不是四个独立功能。

---

## 4. 闭环：问 → 答 → 记 → 归 → 复 → 回

```
         ┌─────────────────────────────────────────────┐
         │                                             │
  问 ──▶ 答 ──▶ 记（自动落卡）──▶ 归（点/错因）──▶ 复（FSRS）
  ▲                                                  │
  └────────────── 回（次日开场 / 周报 / 先修提醒）◀──┘
```

| 步 | 你要做的 | 她自动做的 | 零摩擦设计 |
|---|---|---|---|
| **问** | 打字 / 拍一页 / 贴一道题 | 判断这是"问点"还是"问题" | 只有一个输入框；拍题与对话同一个组件 |
| **答** | 看 | 先答案、再解析；不确定就说不确定 | 不猜、不编；公式可读 |
| **记** | **什么都不用做** | 回答结束异步落 1–3 条：题卡 / 知识卡 | **默认已记，给「撤销」**；不弹确认框 |
| **归** | 偶尔改一下 | 题→知识点（主考点+权重）、错因初判、难度、年级 | 模型先填，用户可改；宁可空着不瞎填 |
| **复** | 一天 5–10 分钟 | 排期、组队、按先修顺序 | 一屏一卡、四档大按钮；可"今天先不练" |
| **回** | 听她说 | 次日回访、先修提醒、周报 | 一天最多一条；可静音 |

> 这条链里**唯一需要你动手的是「问」和「评」**。其它都不该有摩擦。
> 一旦要求你"整理错题本""给题目打标签"，这个产品就退化成 Anki 了。

---

## 5. 她怎么知道"你不会"：证据分级

不要做"自动判定"，做**证据累积**。每条证据有来源、权重、可撤销。

| 信号 | 例子 | 权重 | 落什么 |
|---|---|---|---|
| 强 | 贴题问「怎么做」且没给答案 | 0.8 | 题卡（待复习）+ 关联点降一档 |
| 强 | 复习评「忘了 / 模糊」 | 1.0 | 点掌握度下调、下次 due 提前 |
| 中 | 问「为什么 X」「X 和 Y 什么区别」 | 0.4 | 知识卡（不是错题），点标"在学" |
| 中 | 拍照整页，人工勾选了某几题 | 0.5 | 题卡（待确认） |
| 弱 | 问定义、确认理解、拓展阅读 | 0.1 | 只记事件，不生成卡 |
| 负 | 「这个我会」「别记了」 | — | 撤销 + 该点降权 |

三条原则：

1. **宁可少记，不可错记**。错了你会关掉整个功能。
2. **全部可撤销**，而且撤销要一秒内完成（卡片右上角一个 ×）。
3. **不把"问过"直接等同"不会"**。掌握度是概率，不是开关。

---

## 6. 错题本怎么"自动"

自动 ≠ 无脑。规则要窄：

**入错题本的三条来源**
1. 对话里贴/问的题（强）——默认入，可撤；
2. 拍照后人工勾选的题（中）——入"待确认"，确认后生效；
3. 复习时答错/评"忘了"的题（强）——自动入。

**不做的**
- 不把整页卷子的每道题都当错题；
- 不自动删题、不自动改你已经编辑过的答案；
- 不为了"看起来完整"编错因。

**题目状态机**

```
待解决 ──答对一次──▶ 复习中 ──连续两次顺利──▶ 已掌握
   ▲                    │
   └──── 又错了 ◀────────┘
```

**错因**：模型给一个初判（概念 / 计算 / 审题 / 步骤 / 粗心），你可以一句话改。
错因是给"下一次她提醒你"用的，比如「你三次都错在审题，不是不会」。

---

## 7. 界面结构：一个会话 + 三个透镜

**不要做成 Tab**。Tab 会让"学习"变成"逛功能"。

- **主界面永远是那一条对话**：输入、回答、她主动开口，都在这里；
- 功能是**消息的展开**：题卡点开是题目详情，知识卡点开是地图上的那个点，复习卡点开是全屏复习；
- 侧栏/抽屉是**翻档案**：题（题库+错题）、点（地图）、复（今日队列）、记忆、本周、设置；
- 首页不是仪表盘，是她今早说的那段话：**今日队列 + 昨天你问过的那件事**。

四个透镜看到的必须是同一份数据：

| 透镜 | 看到的 | 由什么驱动 |
|---|---|---|
| 题库 / 错题本 | 题 | `question` + `mistake` |
| 知识地图 | 点 | `kp` + 掌握度 |
| 今日队列 | 复习卡 | `card` + `review_log` |
| 记忆 | 她记住的你 | `memory` + `event` |

---

## 8. 她主动说什么（陪伴感的真正来源）

不是提醒，是**判断**。四种，一天最多一条：

1. **昨日回访**：「昨天你问过钠和水，先来一道变式。」
2. **先修提醒**：「这个点连着两次没答上来，先退回 Y。」
3. **周报**：「这周 12 个问题，7 个在函数单调性，3 个是同一类审题错。」
4. **断签回归**：「三天没见，从 5 张卡开始，不多。」

边界：
- 不评价人（「你又粗心」）；
- 不刷数字（积分、徽章、排行榜一律不做）；
- 不连发、不弹窗轰炸；可一键静音；
- 她说的每句话都要能点开对应的东西。

## 9. 数据模型：现有 + 要补

**已有（M1 / M1.5 / 地图）**

```
kp            知识点树 + 先修边（6170 点 / 303 章 / 4369 边）
question      题干、答案、解析、年级、难度、裁图、指纹去重
question_kp   题 ↔ 点多对多 + 权重 + 主考点
memory        她记住的长期事实/偏好
```

**要补（M2 / M4）**

```
mistake       question_id, error_type, status, 我的原话, 来源, 错次
attempt       每次重做：时间、对错、用时、评分
card          FSRS 字段（due, stability, difficulty, reps, lapses…）
review_log    只追加：卡、时间、档位、间隔 —— 训练 FSRS 的唯一数据源
event         对话事件：学科、摘要、kp_ids、原话片段
note          「我的笔记」，与 AI 解析分家
kp_mastery    派生表：掌握度 + 证据数 + 最近证据（可由 review_log 重算）
```

**派生关系**

```
掌握度(kp)   = f(问过、错次、复习评分、时间衰减)
地图颜色     = 掌握度
队列排序     = due + 先修未达标的降权 + 每日预算
周报         = review_log + event 的聚合
```

> 掌握度必须是**可重算的派生值**，不能是手工字段。这样模型换了、规则改了，历史还能重跑。

## 10. 先做哪一段：一条能跑通的最小闭环

不要先做图谱、不要先做导出。先做**「问完真的会回来找你」**这一段（约 1–2 周）：

| # | 做什么 | 验收 |
|---|---|---|
| 1 | 回答结束自动沉淀：**题卡 / 知识卡 + 撤销** | 问一道题，3 秒内库里多 1 条待复习 |
| 2 | 建 `mistake / attempt / card / review_log` 四张表，接 `py-fsrs` | 迁移 up/down/up 通过 |
| 3 | 今日队列 + 四档评分 + 复习页 | 评「忘了」，下次 due 变今天 |
| 4 | 错题本页（全部错题 / 知识分类 双泳道） | 能按知识点聚合，能改错因 |
| 5 | 地图按掌握度着色 | 评完分，地图颜色跟着变 |

**总验收**：连续 7 天打开都有队列；第 2 天她主动提起你第 1 天问过的东西。

这一段做完，产品才从"能用的题库"变成"会记住你的助理"。之后的 M4 自动沉淀增强、M3 先修闸门、M5 周报推送，都是在这条链上加厚。

---

## 11. 明确不做

| 不做 | 为什么 |
|---|---|
| 题库大全 / 搜题工具 | 题多不是价值，**记住你哪道不会**才是 |
| 手动整理错题本 | 一旦要你整理，你就不会整理 |
| 游戏化（积分/徽章/排行） | 对单用户无效，会稀释复习 |
| 一上来做知识点级调度 | 先把题目卡跑顺，知识点掌握度只做聚合（自研风险见 docs/03） |
| 把每条消息都变成任务 | 噪音会毁掉信任 |
| 多用户 / 班级 / 分享 | 这是自己的本子 |

## 12. 和现在代码的差距

| 能力 | 现在 | 差什么 |
|---|---|---|
| 问她、答 | ✅ 对话 + 工具 + 联网 | — |
| 拍题入库 + 答案解析 | ✅ 拍题 → 题库 → 后台解析 | 连拍/队列收尾 |
| 知识点标签 / 地图 | ✅ 树 + 边 + 地图 | 掌握度着色 |
| 自动记住「这题不会」 | ❌ | `deposit_from_chat` + `mistake` |
| 自动记住「这个点不懂」 | ❌ | 证据事件 + `kp_mastery` |
| 复习 | ❌ | `card/review_log` + FSRS + 队列 |
| 回访 / 周报 | ❌ | 主动消息 + 统计 |

**下一件事只有一件：让「回答完」到「明天回来复习」这条路通。**
