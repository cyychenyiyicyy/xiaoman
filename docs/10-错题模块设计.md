## 1. 逐屏拆解：它到底做对了什么

### 图 1 · 全部错题

| 它做的 | 为什么有效 | 我原稿 |
|---|---|---|
| **顶部双泳道：全部错题 / 知识分类** | 同一个东西的**两个视角**（时间 / 知识），不是两个功能 | ❌ 只有一列列表 |
| **双栏卡片，卡片里是题干原文**（公式正确渲染） | **错题是"认出来"的动作**——你找的是"那道长什么样的题" | ❌ 一行摘要「导体棒在磁场中运动 · 方向判反」，**那是我替你总结的，你反而认不出** |
| **卡片底部知识点 chip** | 一眼知道这题考什么，不用点进去 | ⚠️ 只在行尾写了个"概念" |
| **按录入日期分组**（09/02、04/08…倒序） | 你记得的是"什么时候做的"，不是"第几题" | ❌ 没有分组 |
| **卡片底部渐隐**（内容被截断） | 不用点就知道"里面还有" | ❌ 无 |
| **5 个常驻筛选 chip** | 不用进二级页就能收窄 | ⚠️ 我只有 3 个，且是横向滚动的等效物 |
| **底部三动作胶囊：录入 / 打印 / 复习** | 把"这个页面之后干什么"常驻化 | ❌ 无 |

> **最关键的一条**：卡片必须显示**题干原文**。这是"清晰"的根源，也是**最大的工程代价**（见 §4）。

### 图 2 · 知识分类

| 它做的 | 为什么有效 |
|---|---|
| **一个知识点 = 一张卡**，知识点名用最大字号 | 这张列表回答的是「**我哪个知识点错得最多**」，一屏就能比出来 |
| **题数**（1 道题 / 2 道题） | 分母，没有它就没法判断轻重 |
| **定义 / 公式摘要**（3 行截断） | 不用点进去就能复习一遍概念——**这一条我完全没想到，价值极高** |
| **绿色 +1 / +2 角标** | "上次看之后新增了几题"，一眼知道哪里在长 |
| **"新添加的知识点" 分节** | 按新鲜度排，而不是按字母/课标 |
| 顶部只剩「年级」一个筛选 | 因为这一层已经按知识点降维了，不需要再筛知识点 |

> **这条我想加上一个它没有的东西：掌握度条**。豆包是**题库管理**（题目归堆），我们是**学习调度**（决定今天练什么）——所以知识点卡上必须有 `0.34` 这种数字，否则没法排序。

### 图 3 · 题目详情

| 它做的 | 为什么有效 | 我原稿 |
|---|---|---|
| **左右翻页 2/24** | 在一个筛选结果序列里**连续翻**，不用退回列表——这可能是三屏里最提升效率的一处 | ❌ 只能返回列表 |
| **查看原图 ›** | 保留原始照片，公式识别错了还能看原卷 | ❌ 无 |
| **知识点 chip 带教材位置**（`集合的包含关系` + `数学/高一上`） | 知识点和"它在课本哪儿"合并成一个 chip，省一行 | ⚠️ 分成两块 |
| **＋ 加知识点** | 标注是一个**持续的动作**，不是录入时的一次性填表 | ✅ 有，但藏在校对页 |
| **书签（已标记）** | 供筛选"已标记"用，是轻量的"回头再看" | ❌ 无 |
| **我的笔记 / 答案解析 分家** | **你的东西和 AI 的东西必须分开**。混在一起会让你以为自己懂了 | ❌ 我只有"解析"和"历次作答" |
| **空状态文案："记录你的错因或者反思"** | 把"写错因"变成一个低成本、被鼓励的动作 | ⚠️ 有备注字段，但没引导 |
| **底部三动作：1对1讲解 / 相似题 / 写笔记** | 回答"看完这题我现在能干什么" | ❌ 我放了"重做"——但**重做是复习队列的事，不是详情页的主动作** |

> 我原稿把「**你的作答 vs 正确答案**」放在主位，那是**判卷视角**。学习的视角是：**我现在要干嘛**（问 / 练相似 / 记一笔）。这是我第二个明显做错的地方。

## 2. 采纳 / 改造 / 不采纳

### 采纳（原样照做）

| # | 做法 |
|---|---|
| 1 | **双泳道：全部错题（时间透镜）/ 知识分类（知识透镜）** |
| 2 | **双栏卡片 + 题干原文**（服务端渲染缩略图，见 §4） |
| 3 | **按录入日期分组**（倒序） |
| 4 | **卡片底部渐隐** + 知识点 tag |
| 5 | **知识分类卡**：知识点名 / 题数 / 定义摘要 / 新增角标 |
| 6 | **详情左右翻页**（在筛选序列里连续翻） |
| 7 | **我的笔记 / 答案解析 分家** + 空状态引导 |
| 8 | **底部动作胶囊**（3 个，常驻） |
| 9 | **查看原图**、**＋加知识点**、**书签** |

### 改造（我们要更狠的地方）

| # | 它 | 我们 |
|---|---|---|
| 1 | 知识分类卡只有题数 | **加掌握度条 + 薄弱排序**（我们是调度，不是题库） |
| 2 | 底部"1对1讲解"跳独立 AI 页 | **"问她" = 回单一对话**，题目自动成为上下文。**我们不需要那个独立页**——这正好是 07 单一会话的收益 |
| 3 | 底部"复习"是全局入口 | **"复习这条链"**：从当前知识点出发，带先修一起练（我们的差异点） |
| 4 | 筛选 5 个 chip 平铺 | 手机 → **3 个 + 「更多」**；平板 → 左栏常驻分组（见 M4） |
| 5 | 多色卡片底色 | **单色赤陶 + 描边**，靠字号和留白分层 |
| 6 | 空状态 "✨" emoji | **不用 emoji**，纯文字 + 内联 SVG |

### 不采纳

| 不抄 | 原因 |
|---|---|
| 底部"打印" | 你不用纸了（或者用 iPad 打印也不是主路径）——**保留但降级到「⋯」里** |
| "内容由AI生成" 免责 | 自用产品，无合规需求 |
| 三个页面各自独立导航 | 与单一会话冲突；错题是抽屉里的二级页 |
| 知识点靠人工维护层级 | 我们用课标树 + 先修边，自动生成 |

## 4. 工程代价：卡片里绝对不能跑 WebView ⚠️

这是本次改版**唯一真正的技术难题**，而且它**影响 M1**。

### 问题

题干带 LaTeX（`{x | −1 < x < 4}`、`ax² + bx − 2`）。渲染方案只有三种：

| 方案 | 一屏 12 张卡 | 结论 |
|---|---|---|
| 每张卡一个 WebView（KaTeX/MathJax） | 12 个 WebView 实例 → **必卡死**（内存 + 布局抖动） | ❌ 不可行 |
| 原生 LaTeX 库（`jlatexmath-android`） | 可用，但**字体丑**、行内混排对齐差 | ⚠️ 仅降级用 |
| **服务端预渲染缩略图** | 就是一张 PNG/WebP | ✅ **选它** |

### 方案：服务端出「题干缩略图」

结构化流水线在产出 Markdown 的同时，多产一张图：

```
stem_md + LaTeX  →  headless 渲染（KaTeX → SVG → PNG @2x）
                  →  question.stem_preview_png（宽度按列宽，高度自适应，上限 3 行）
```

三个好处：
1. **列表滚动丝滑**，和图片列表没区别；
2. **卡片高度可控** → 双栏瀑布流不会在滚动时抖动（这个坑豆包一定踩过）；
3. **离线直接缓存图**，不依赖 WebView 内核版本（你那台讯飞是 Chrome 101，图更保险）。

详情页则只用 **1 个复用的 WebView** 渲染完整题干（KaTeX 离线包 ~300KB），或原生文本 + `jlatexmath` 保底。

### 连带影响（现在就要做，不能等）

> **M1 的结构化输出必须同步产出 `stem_preview_png`。**
> 否则等你 M2 做错题本时，库里的几万条题全部要回填渲染一遍——这是典型的"当时省一步、后来补三天"。

## 5. 数据模型增量

在 03 §5 的 8 张表上加这些字段/表：

```sql
-- question 增补
ALTER TABLE question ADD COLUMN stem_preview_png TEXT;      -- 缩略图路径（服务端渲染）
ALTER TABLE question ADD COLUMN textbook_ref    TEXT;       -- 「数学 / 必修一」
ALTER TABLE question ADD COLUMN bookmarked_at   TIMESTAMPTZ;
ALTER TABLE question ADD COLUMN source          TEXT;       -- 手机拍｜PDF｜手工

-- kp 增补（供知识分类卡）
ALTER TABLE kp ADD COLUMN summary_md     TEXT;   -- 定义/公式摘要（3 行内，来自课标或生成后人工校）
ALTER TABLE kp ADD COLUMN textbook_ref   TEXT;
ALTER TABLE kp ADD COLUMN q_count        INT DEFAULT 0;   -- 物化计数，写入时维护
ALTER TABLE kp ADD COLUMN new_count      INT DEFAULT 0;   -- 上次查看后新增
ALTER TABLE kp ADD COLUMN last_seen_at   TIMESTAMPTZ;

-- 笔记（"我的笔记"，与 AI 解析分家）
CREATE TABLE note (
  id TEXT PRIMARY KEY, question_id TEXT REFERENCES question(id),
  body_md TEXT, created_at TIMESTAMPTZ, updated_at TIMESTAMPTZ
);
```

**三条实现要点**：

1. `new_count` 用「`created_at > kp.last_seen_at`」算，打开知识分类页时清零 → 角标行为自然。
2. `summary_md` 是最容易做烂的字段：**不要纯靠模型生成**（会写得像教科书废话）。建议 **课标/教材原文导入 + 模型压缩到 3 行 + 人工抽查**。
3. `stem_preview_png` 存对象存储（和题目原图一起），**不入库 blob**。

## 6. 接口增量

```
GET  /api/v1/questions?view=time&status=open&kp=&error=&limit=20&cursor=
        → items[{ id, stemPreviewPng, kpNames[], textbookRef, wrongCount, createdAt, bookmarked }]
GET  /api/v1/questions?view=kp&subject=math
        → items[{ kpId, name, textbookRef, qCount, newCount, summaryMd, mastery }]
GET  /api/v1/questions/{id}/neighbors?filter=<cursor-token>
        → { prevId, nextId, index, total }        # 支撑 2/24 翻页
POST /api/v1/questions/{id}/note        { body_md }
POST /api/v1/questions/{id}/bookmark
POST /api/v1/questions/{id}/ask         # 等价于往对话里发一条带 questionId 上下文的消息
```

**`/ask` 是关键**：它不返回答案，而是**插入一条对话消息**（`question_card`），把用户带回 P0 主界面并带上题目上下文。这就是「问她」不需要独立讲解页的原因。

## 7. 平板布局（M4）

```
rail 76 │ 筛选 224 │ 卡片网格（GridCells.Adaptive(minSize = 280.dp)） │ 详情 520
```

- 网格列数**不用写死**：`LazyVerticalGrid(GridCells.Adaptive(280.dp))` → 1280dp 宽自动出 2–3 列，切到手机自动 1 列；
- 筛选项做成左栏常驻（状态 / 视图 / 知识点 / 错因），比顶部 5 个 chip 更省空间也更清楚；
- 详情栏和对话页一样用「选中即显示」，**返回栈由 `selected` 驱动**（09 §9 同一条纪律）。

## 9. 一句话记住

> **错题本的清晰度 = 你能不能在 2 秒内"认出"那道题，以及能不能一屏比出"哪个知识点最烂"。**
> 前者靠题干原文（所以要预渲染缩略图），后者靠知识点聚合卡（所以要 summary + 掌握度 + 题数）。**其它都是装饰。**
