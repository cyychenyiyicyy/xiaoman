## 1. 模型：按 provider 分，模型身份是二元组

### 1.1 你说对了三件事

| 你说的问题 | 确认 | 依据 |
|---|---|---|
| 有莫名其妙的描述文本 | ✅ 确实一堆 | `每日上限／超出的顺延到明天`、`只对这一科／物理用这个模型，其它跟随默认`、`模型目录来自 Pi（pi update --models），这里只是选`…… |
| 不该写价格 | ✅ | 自定义端点（`models.json` 里手填 baseUrl）我们根本不知道价格，写死就误导 |
| 多 provider 同一个模型 | ✅ **这是硬事实** | Pi 的模型引用就是 `provider/model`：`azure/gpt-5.4`、**`azure/deepseek-v4-pro`** |
| 缺模型管理页 | ✅ | 没有入口去配 provider / 拉目录 |
| Pi 有多 provider 现成设计 | ✅ | 见 §1.2 |

### 1.2 Pi 的做法（原文摘要）

| 事实 | 出处 |
|---|---|
| **模型按 `provider/model` 引用**，`--model azure/deepseek-v4-pro` —— 同一个 DeepSeek 在 Azure 下是独立一条 | pi.dev/docs/latest/providers |
| **provider 是认证的单位**：`/login [provider]` 列出 provider，各自支持 OAuth 或 API Key，凭据存 `auth.json` | 同上 |
| **`/model` 只显示"provider 有可用认证"的模型** | pi.dev/docs/latest/models |
| provider 分**区域版**：`MiniMax` 与 `MiniMax (China)`、`Moonshot AI (Global and China)`、`ZAI Coding Plan (Global/China)`、`Qwen Token Plan Team/Individual (±China)`、`Xiaomi MiMo Token Plan (China/Amsterdam/Singapore)` | providers |
| **自定义端点**走 `models.json`（`baseUrl` + `api` + `models`），不是新建 provider 类型 | models |
| **目录可刷新**：`pi update --models` 强制刷新已缓存的 catalog | models |

### 1.3 所以界面这么改

**模型身份 = `provider / model`**，界面三处体现：

| 位置 | 形状 |
|---|---|
| 输入框胶囊 | `千帆`（小字灰）+ `deepseek-v4-flash`（正文）+ `⌄` |
| 模型弹层 | **按 provider 分组**，组头 = provider 名 + 认证状态（已连接 / 未连接） |
| provider 详情 | 认证 / 端点 / 模型列表 / 更新目录 / 断开 |

三条规则：

1. **只显示已认证 provider 的模型**（Pi 行为）——避免选到一个用不了的。
2. **未连接的 provider 也显示**，但只有一行「去连接 ›」，点进模型管理。**不显示它的模型**。
3. **不写价格**。要比就比上下文长度（`1M` / `128K`），那是确定的事实。

弹层底部固定一行 **「模型管理 ›」**——选择器和配置入口在同一处，不用绕回设置。

## 2. 模型管理（新增）

三级结构，和设置页共用 `sgroup / scard / srow`：

```
模型管理
├─ 已连接        千帆 Token Plan (11) · 火山方舟 (5)
├─ 未连接        Anthropic · OpenAI · OpenRouter      → 连接
├─ 自定义        添加 OpenAI 兼容端点                   → baseUrl + apiKey + models
└─ 目录          更新模型目录 · models.dev
```

**Provider 详情**（V5）四段：

| 段 | 内容 |
|---|---|
| 认证 | 状态 / API Key（打码后 4 位）/ 端点 |
| 模型 | 列表 + 每行上下文长度；当前选中带勾 |
| 动作 | 更新目录 · 断开 |

> 「更新目录」写 **models.dev** —— 你说得对，目录该从 models.dev 来。技术上它是"把 models.dev 的条目灌进 `modelOverrides`"（`docs/06 §6.3`），Pi 自带 catalog 做兜底。
