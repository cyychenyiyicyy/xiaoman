## 0. 一句话结论

设计与规范已经够写代码了，**但「代码」不是从 Android 界面开始的，是从数据契约开始的。**
M0 的重心是 `server/`（表 + 迁移 + `/health` + 验收脚本），Android 只出骨架、构建交给 GitHub Actions，Pi 的一天验证独立并行。

## 2. 与 README 的 4 处偏离（需拍板，不默认执行）

## 3. 总策略：契约先行 · 垂直切片 · 三条泳道

### 3.1 契约先行

先产出两样东西，再写两端：

1. **DDL + Alembic 迁移**（13 张表，见 §5 S0.3）；
2. **`/openapi.json`**（FastAPI 自动出）。

Android 的 DTO **由 OpenAPI 生成，不手抄**。这样「改一个字段要同时动三端」这条 monorepo 代价，被压缩成「改契约 + 重新生成」。

### 3.2 垂直切片

每个切片必须自带 **产物 / 验证命令 / 失败长什么样** 三件套。不接受「先写完再调」。

### 3.3 三条泳道（写作用域不重叠）

| 泳道 | 作用域 | 阻塞在 |
|---|---|---|
| server | `server/**` `data/**` | 无（**主线**） |
| android | `android/**` `.github/workflows/android.yml` | `openapi.json`（只读，不阻塞骨架） |
| agent | `agent/**` | M4 才需要 server 内部工具端点 |

**唯一汇合点**：`openapi.json` 与 `data/kp/*.json`。两者只增不改；要改必须同时通知三条泳道。

### S0.2 本机 PostgreSQL 18（1 小时）

- 产物：`winget install PostgreSQL.PostgreSQL.18` → 服务运行；`xiaoman_dev` 库；`server/.env.example`；`scripts/db_bootstrap.ps1`
- **纪律**：脚本开头 `$PSScriptRoot`，不许写死 `C:\Users\...`（AGENTS §4.1 的历史教训）
- 验证：
  ```powershell

  psql -d xiaoman_dev -c "\dt"                # 此时应为空
  ```
- 失败：版本 < 18 / 连不上 / 脚本里出现绝对路径

### S0.3 表结构 + 迁移（M0 的真正核心，1–2 天）

产物：`server/app/db/models.py`（SQLAlchemy 2 声明式）+ `server/migrations/`（Alembic）+ 三条**落到 DDL** 的约束。

**13 张表** = `docs/03 §5` 的 9 张 + `docs/10/11/16` 的增补 3 张 + `capture_task`：

| 来源 | 表 |
|---|---|
| 基线 9 张 | `kp` `kp_edge` `question` `question_kp` `mistake` `attempt` `card` `review_log` `fsrs_param` |
| 增补 3 张 | `note` `event` `kp_cross_ref` |
| 本文补 D4 | `capture_task` |

三条约束**必须写在 DDL/触发器里，不能只写应用层**（应用层挡不住手工 SQL 和未来的 agent 写入）：

| 约束 | 实现 | 为什么不能用应用层 |
|---|---|---|
| `kp_edge` 只能同学科内 | `BEFORE INSERT OR UPDATE` 触发器：取两端 `kp.subject` 不等则 `RAISE EXCEPTION` | agent 的 `kp_edge_add` 会走另一条写入路径 |
| `review_log` 只追加 | `BEFORE UPDATE OR DELETE` 触发器 `RAISE EXCEPTION` | 它是训练 FSRS 参数的**唯一**数据源，一旦被覆盖就没法回滚 |
| 所有表带 `schema_version` | 每表 `schema_version INT NOT NULL DEFAULT 1` | README §11「数据要活十年」的可迁移前提 |

其余硬点：
- `card` 的字段名**照 FSRS 规范原样**（`state/due/stability/difficulty/elapsed_days/scheduled_days/reps/lapses`），这样能直接喂 `py-fsrs`，不写映射层；
- `question` 必须同批带上 `stem_preview_png` 列（硬规则 3：允许 M1 填，不许 M2 回填）。

验证（**三次迁移，缺一次不算过**）：
```powershell
alembic upgrade head; alembic downgrade base; alembic upgrade head
psql -d xiaoman_dev -c "\dt"        # 13 张（+ alembic_version）
```
失败：任一跑报错 / 表数不对 / 触发器没生效（要专门写一个 `INSERT` 跨科边的用例，期望被拒）

### S0.4 FastAPI 骨架 + `/health`（半天）

- 产物：`app/main.py`、`app/api/v1/router.py`、`app/db/session.py`、`app/core/config.py`（`pydantic-settings` 读 `.env`）
- `/health` 返回 `{ok, db:"ok", alembic_head:"...", version}`
- 依赖**精确锁**（`docs/05 §4.2` 要求 `uv.lock`）：`uv init` + `uv lock`，禁止 `>=` 反推
- 验证：`uvicorn app.main:app` → `curl /health` 200 且 `db:"ok"`；`pytest -q` 全绿
- 失败：/health 500 / 依赖没锁

### S0.5 `verify.py` —— 先立规矩，比写功能重要（半天）

这是**唯一一个「防自欺」的切片**，必须排在业务前。

- 结构：`server/tests/verify.py --only schema|migration|fsrs|export|api`
- 三条纪律（`docs/05 §4.3`）：
  1. 开跑前**先删旧报告** `reports/verify.json`（崩在半路不会残留上次结论）；
  2. 结尾 `sys.exit(1 if failures else 0)`；
  3. **`--selftest` 主动注入一个假失败** —— 用来证明脚本真的会 exit 1。
- 当前实现 `schema` + `migration` 两项；`fsrs` / `export` 留桩，输出 `SKIP`（**不计 FAIL，也不许全绿通过**）

验证：
```powershell
python -m tests.verify --only schema,migration      # exit 0
python -m tests.verify --selftest                   # 必须 exit 1
```
失败：`--selftest` 也 exit 0 → **脚本无效，立即停手修脚本**（历史上就是「31 个 FAIL 却 exit 0」把坏包放上线）

### S0.6 Android 骨架（只写，不本机构建，1 天）

### S0.7 CI 两条流水线 + 路径过滤（1 天）

## 10. 数据库环境策略（2026-11-14 定稿 + 实测修订）

### 10.1 三环境

| 环境 | 在哪 | 库 | 用途 | 铁律 |
|---|---|---|---|---|
| **dev** | 本机 | `xiaoman_dev`（PG **18.7**，端口 **5434**） | 日常开发 + 全部自动验收 | 可随时 `DROP SCHEMA`；**只放 fixture，永不装真实数据** |
| **staging** | 服务器 | `xiaoman_staging` | 里程碑末尾端到端冒烟（Caddy、手机连通、备份） | 不手工改表 |
| **prod** | 服务器 | `xiaoman` | 真实使用 | **只由迁移脚本变更** |

### 10.2 已实测的环境事实（2026-11-14）

- 本机原装 **PostgreSQL 16.15** 的服务被禁用（`postgresql-x64-16 = Stopped/Disabled`）；
- `winget install PostgreSQL.PostgreSQL.18` 成功装了 **18.7**，但它装成系统服务、跑在 **5432**，且超级用户密码是安装器交互设的，**我们不知道**；
- 因此 dev 库不走系统服务，而是**用 PG18 的二进制在项目目录里另起一个实例**：
  ```
  data/pgdata18   数据目录（已 gitignore）
  5434            trust 认证，只监听 127.0.0.1
  pg_ctl start -D data/pgdata18 -o "-p 5434" -l data/pg18.log -w
  ```
- **Windows 上 `postgres.exe` 拒绝以管理员身份直启**，必须经 `pg_ctl`（它会降权）。这条踩过一次，记为坑。

### 10.3 为什么不在服务器上开发

| 理由 | 量级 |
|---|---|
| 反馈延迟 | 本机回环 <0.1ms vs 公网往返 20–50ms，一轮 pytest 差 **一个数量级** |
| 爆炸半径 | 开发期要 `dropdb` / `downgrade base` / 灌脏数据，本机随便推倒，生产库不行 |
| 迁移纪律 | `upgrade→downgrade→upgrade` 必须在**空库**上验；在服务器上跑等于拿生产库试迁移 |

服务器只做三件本机验不了的事：**Docker compose 能否起来、手机在国内网络能否连上（R7）、备份能否真恢复（R4）**。
