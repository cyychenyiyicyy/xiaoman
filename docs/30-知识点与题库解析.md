# 30 · 知识点与题库解析

> 目标：**题库自己长解析**。拍进来一道题，后台补「答案 + 解析 + 知识点 + 年级 + 难度」；
> 知识点不是手写的，是从公开数据集导进来的教材树，先把 M3「知识点串联」的地基打上。

对应代码：`server/app/services/{solve,knowledge}.py` · `server/app/api/{questions,kp}.py` ·
`server/scripts/{import_kp,relink_kp}.py` · `web/app.js`（题库页）· `web/theme.css`

## 1. 做了什么

## 2. 知识点数据：从哪来

**来源**：[`mmlong818/k12-knowledge-points`](https://github.com/mmlong818/k12-knowledge-points)
《K12 知识点数据集》—— 从国家中小学智慧教育平台的教材正文抽取，不是手写课程表。

| 项 | 值 |
|---|---|
| 许可证 | PolyForm Noncommercial 1.0.0（个人学习使用允许，**禁止商用**） |
| 取用的分组 | `split/高中/{语文,数学,英语,物理,化学,生物,思政,历史,地理}.json` |
| 本库实际导入 | **6161 个知识点 / 303 个章节节点 / 4369 条关系边**（同名合并 12 条） |
| 学科映射 | 数据集的 **思政 → 小满的 政治**，其余同名 |
| 年级 | 教材有 `grades` 就用；高中的 `必修 → 高一`、`选择性必修 → 高二`、`选修 → 高三` |
| 难度 | 数据集 `annotations.difficulty`（0–1）存进 `kp.difficulty`，和题目的 1–5 难度分开 |

导入是**幂等**的（源 uuid 作主键 upsert，章节节点用 `subject|模块|章` 的 hash）：

```powershell
cd server
.venv\Scripts\python.exe -m scripts.import_kp              # 九科全量（首次约 19MB 下载）
.venv\Scripts\python.exe -m scripts.import_kp --offline    # 只用 data/kp-raw 缓存
```

> 下载有 4 次重试；缓存放在 `data/kp-raw/`（已在 `.gitignore`）。重复跑不会长数据，也不会丢已有的题目标签。

### 2.1 树的结构

- `kp.kind='chapter'`：教材**章节骨架**（如「第一章 物质及其变化」），只用来分组，不参与打标签；
- `kp.kind='point'`：可打标签的知识点，`parent_id` 指向章节；
- 章节路径取 `textbooks[].chapter_path[0]`；高中没有年级的模块用 `module`（如「选择性必修1 化学反应原理」）区分。

### 2.2 关系边（为「知识点串联」准备）

`kp_edge.type` 三种：`prerequisite`（前置）、`leads-to`（导向）、`related`（相关），
全部来自数据集的 `relations`，**只同学科内**——迁移里用触发器强制：

```sql
CREATE TRIGGER trg_kp_edge_same_subject
BEFORE INSERT OR UPDATE ON kp_edge
FOR EACH ROW EXECUTE FUNCTION kp_edge_same_subject();
```

跨科关系以后走 `kp_cross_ref`（AGENTS §3.3），不进先修闸门。
查关系：`GET /kp/{kid}/neighbors`。

## 3. 数据模型（迁移 `c2f9a1d4e6b7`）

```text
kp            id / subject / name / name_norm / kind / parent_id / grade / module / chapter
              summary_md / aliases(jsonb) / difficulty(0–1) / kp_type / source / source_id
              q_count(物化计数) / sort
kp_edge       from_kp_id / to_kp_id / type / subject(触发器写) / source
question_kp   question_id / kp_id / weight / is_primary   ← 多对多加权，主考点唯一
question      + grade(高一/高二/高三) / difficulty(0–5) / solve_status / solve_error
              + solved_at / ai_meta(jsonb，存模型原始输出)
```

`solve_status`：`''`（没跑过）→ `queued` → `running` → `done` / `failed` / `skipped`。
`skipped` = 没连 provider，不假装有解析。

## 4. 解析流水线

```
拍题（capture_task）→ 人工框选 → confirm 入库
                              ├─ 写 question（题干 / 选项 / 原图裁图 / 指纹去重）
                              └─ 后台 solve_many(ids)
                                    ├─ 取当前 provider/model（mock 直接 skipped）
                                    ├─ 题干 + 选项 + 同科候选知识点 → 一次 JSON 输出
                                    └─ 写 answer_md / solution_md / grade / difficulty
                                        + tag_question（知识点对树，落 question_kp）
```

### 4.1 提示词约束（`services/solve.py`）

- 只输出 JSON：`answer / solution / grade / difficulty / knowledge[]`；
- 答案：选择题只给字母，填空用「/」分隔，解答题给最终结果；
- 解析：先点考点，再写关键步骤与易错点，≤160 字，公式 `$...$`；
- 知识点：2–4 个，**优先从候选里选**（候选由题干 2-gram 重叠从同科树里挑 36 个）；
- 条件不足就写「条件不足」，**不猜答案**；
- 有裁图且模型 `supports_images` 时把图一起给模型；模型不认图（HTTP 4xx）自动退回纯文本重试一次。

### 4.2 知识点落到树上（`services/knowledge.resolve`）

优先级：**教材树 > 模型补建的点**。匹配顺序：

1. 整名归一匹配（去空白/标点、小写）；
2. 别名匹配；
3. 互相包含 + 前缀放宽（「牛顿第二定律」→「牛顿第二定律的表述与物理意义」）；
4. 仍没有：按 `与 / 、 / 和 / 及` 拆开再匹配一次；
5. 都没有才新建 `kp.source='llm'` 的点（挂不到章节，先保证标签不丢）。

> 改动匹配规则后，可跑 `python -m scripts.relink_kp` 把已有题目的标签重新对一遍（**不再花模型钱**），
> `--apply` 才会写库，同时清掉没被引用的模型点。

### 4.3 触发点（三处）

| 位置 | 行为 |
|---|---|
| 拍题确认入库 | 每道新题 `solve_status=queued`，后台逐题跑 |
| 对话里 `question_add` 收录 | 缺解析时后台补（**不覆盖**模型已给的答案） |
| 题目详情「重新生成解析」 | `POST /questions/{id}/solve?overwrite=true` |
| 题库「补解析 n」 | `POST /questions/solve-missing`（一次最多 20 题） |

## 5. API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/kp/tree?subject&q&kind&limit` | 扁平返回，`parent_id` 建树 |
| GET | `/kp/search?q&subject&limit` | 名称 / 别名搜索（编辑器用） |
| GET | `/kp/stats` | 每科点数 / 章节数 / 已打标题数 |
| GET | `/kp/{id}` | 详情 + 子节点 + 先修 / 后继 |
| GET | `/kp/{id}/neighbors` | 关系图（串联用） |
| GET | `/questions?subject&grade&difficulty&kp&q&has_answer` | 题库筛选（`kp` 传章节 = 其下所有点） |
| GET | `/questions/{id}` | 含 `kps[]`、`grade`、`difficulty`、`solve_status` |
| PATCH | `/questions/{id}` | 题干 / 答案 / 解析 / 选项 / 年级 / 难度 / `kps: [id]` |
| POST | `/questions/{id}/solve` | 重新生成（后台） |
| POST | `/questions/solve-missing` | 批量补解析（后台） |

## 6. 界面

### 6.1 题库页（L0）

```
题库                             7 题
[搜题干.............] [搜索] [+ 拍题]     ← 拍题是唯一 filled
[全部 7][语文][数学]…[地理]                ← 学科
[年级][难度][知识点] [重置]     [补解析 n]  ← 筛选，点开是弹层
今天
┌ 化学 高一 较易 ───────────────┐
│ 题干（3 行截断）          [缩略图]│
│ [主考点][知识点2] [+2]          │
│ 答案 B                        │  ← 解析中… / 解析失败 / 待补解析
└──────────────────────────────┘
```

- 拍题弹层与对话的「＋ → 相机/相册」是**同一个组件**，只是 `intent='bank'`：
  标题「收进题库」、可先选学科、隐藏「题库」入口、确认按钮是「收进题库（n 题）」；
- 收完回题库并**每 2.6s 轮询**，解析中的卡片自动补上答案 / 标签 / 年级 / 难度；
- 空态给一个「拍题」动作；错误态给「返回对话」。

### 6.2 题目详情

题干卡（题型 / 学科 / 年级 / 难度）→ 知识点 chips（主考点填底色）+「编辑」→
答案 →（虚线分隔）解析 → 原图 → 底部「编辑 / 重新生成解析 / 引用该题」。

### 6.3 编辑与知识点弹层

- 编辑弹层：题干 / 选项 / 答案 / 解析 / 年级下拉 / 难度下拉；
- 知识点弹层：搜索 + 已选置顶 + 点击即存（`PATCH kps`），筛选模式下点一行即按该知识点筛。

## 8. 已知限制 / 下一步

| 项 | 说明 |
|---|---|
| 只导了**高中** | 初中九科可复用同一个脚本（`--subjects` 只认高中文件名，要加学段参数）；复习若涉及初中知识需要在 M2 前补 |
