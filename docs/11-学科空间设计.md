# 11 · 学科空间：不分会话，但按学科分

> 用户质疑（2026-11-14）：**"如果单独一个会话的话，我这些语文、数学、英语、物理、化学这么多科目的会话全部都混在一起，其实也不是很好。"**
> 这个质疑成立。本文修订 07 的 §7（那里我写的是"界面一个对话、内部按学科分 session、消息合并渲染"——**合并渲染就是混在一起**）。

---

## 1. 先认错：我把两条轴混成了一条

「单一会话」这个设计里有两条**互相独立**的轴，07 把它们并成了一条：

| 轴 | 说明 | 应该 |
|---|---|---|
| **关系轴**（她是谁） | 人格、语气、对你的了解、记忆、习惯 | **必须单一**。九个"她"是灾难 |
| **内容轴**（在聊什么） | 语文/数学/英语/物理/化学…知识体系互不相通 | **必须分开**。混在一起会互相污染 |

我原方案是「界面一个流、内部九个 session、**消息合并渲染**」。合并渲染 = 你在物理里往下翻，中间插进来三段英语对话——**正是你担心的那种乱**。而且更糟的是：

- Pi 的 compaction 按 session 做，但**你看到的是混的**，滚动时上下文和你说的话对不上；
- 分享/回看时，想找"上周那道数学题怎么讲的"要穿过一堆物理记录。

**所以修正是：关系不变，内容分空间。**

---

## 2. 解法：**不是九个会话，是九个"学科空间"**

类比是 **Claude Projects**：一个账号、一套人格，但项目各自有自己的对话；项目之间共享你这个人。

| | 我们 |
|---|---|
| **伙伴** | 一个（小满）。人格、语气、对"你这个人"的记忆 **全局一份** |
| **学科空间** | 九个（高一）。每个空间里是**一条无限长的连续对话**——**依然没有会话列表，依然不新建** |
| **切换** | 顶部一个学科胶囊。切换 = **换空间**，不是"新建对话"，历史永远在 |
| **跨科的东西** | 记忆面板、知识地图、错题本、本周、复习队列 → **全局**（可筛学科） |

**一句话：像和同一个老师聊天——你今天只聊物理，明天只聊英语；但老师记得你所有科目。**

这条修正的好处是：**07 里"没有会话列表、像微信好友"的设计完全没有被破坏。** 你在"物理"空间里，那就是你和她在物理上的连续对话，一直往下长。变的只是：**你有九个这样的空间，而不是一个把所有科都塞进去的。**

---

## 3. 界面：学科胶囊 + 「全部」概览

### 3.1 顶部改一个东西

```
改前：  [头像] 小满 · 今天陪你学物理            [⋯]
改后：  [头像] 小满        [ 物理 ▾ ]          [⋯]
```

- 那个 `物理 ▾` 就是**唯一的导航**，点开是十项：**全部 / 语文 / 数学 / 英语 / 物理 / 化学 / 生物 / 政治 / 历史 / 地理**
- 当前学科高亮；每项右边显示**该科的待办数**（如 `物理 12`）
- 切换后**滚动位置各自记住**——从数学切到物理，回到上次看到的地方

### 3.2 「全部」不是仪表盘，是她今早说的那段话

这是关键设计：**「全部」也必须长得像对话**，否则首屏就变成了一屏卡片，07 说的"她就是首页"就没了。

```
小满  07:30
早上好。今天四科有事：

┌ 物理  12 张待复习 · 受力分析占一半        [继续] ┐
┌ 数学   5 张 · 集合的包含关系还薄弱        [继续] ┐
┌ 英语   3 个词到期 · 上次错在拼写          [继续] ┐
┌ 化学   2 道 · 昨天错的是方程式配平        [继续] ┐

先从最多的开始，还是你有别的安排？
```

点任一科 → **切到该学科空间**（不是打开一个新页面）。

### 3.3 三处必须保持"全局"

| 全局的东西 | 为什么 |
|---|---|
| **记忆面板**（她记得的） | 她记得"你物理弱"和"你英语作文差"是同一个你。**不按科拆**，但每条可标来源科 |
| **复习队列** | "今天练什么"是全局问题。跨科混排（01 §0.1 已定），只在顶部标注"今天主要在物理" |
| **知识地图 / 错题本 / 本周** | 默认显示当前学科，但一键可切"全学科" |

## 4. 主动消息怎么发（别变成九科催收）

原方案「每日开场一条」在九科下会爆。规则改成：

| 谁 | 发在哪 | 条件 |
|---|---|---|
| **跨科汇总** | 「全部」空间，**一条** | 每天一次。只列**当天有事**的科目（到期卡片 > 0 或有待重做错题），通常 2–4 科 |
| **单科开场** | 该学科空间，**≤2 行** | 只在**当天该科有任务**时发。没任务的科**完全不发** |
| 遗忘预警 / 周报 | 「全部」 | 不变（1 条/天、1 条/周的上限仍然有效） |

> **硬规则：一个学科空间里，一天最多 1 条她主动发的消息。** 九科 = 理论上限 9 条，实际按任务数通常 2–4 条，且都分散在不同空间里——你打开哪科才看到哪科，**不会在同一个屏幕上被堆满**。这比"九科挤在一条流里"好得多。

---

## 5. 跨科提问怎么办

你会问："这个物理题要用到数学的什么？"

| 情况 | 处理 |
|---|---|
| 在**物理空间**问，但答案需要数学知识 | **不切空间**。当前 session 回答，工具跨库查数学的知识点和掌握度；引用处标 `来自数学` 的 chip |
| 明确要换学科（"我们来看英语吧"） | 她**问一句确认**："要切到英语吗？" → 切 |
| 在「全部」里直接问 | 她**先判断科**，判断不了就问一句："这是哪科的？"（只问一次，然后进该科空间回答） |

**原则：空间切换必须是显式的（你点，或你明确说），她不能自作主张把你的物理对话变成数学对话。**

## 6. 技术落点

改动比想象的小——因为 07 本来就把 session 按学科分了，只是**渲染层没有分**。

### 6.1 Pi session 映射（不变，但含义变了）

```
1 个学科空间 = 1 个 Pi session（长期存在）
每个 session 只收该学科的消息 → compaction 不会串味
```

### 6.2 消息表（已就绪）

```sql
-- 03 §5 的表已经有 subject 字段，只需明确语义
message.subject TEXT NOT NULL            -- 'physics' | 'math' | ... | 'all'
-- 「全部」空间里她发的汇总消息：subject = 'all'
```

**查询**：

```sql
-- 某学科空间的消息流（唯一的主查询）
SELECT * FROM message WHERE subject = :subject ORDER BY ts DESC LIMIT 50;
-- 全部空间
SELECT * FROM message WHERE subject = 'all' ORDER BY ts DESC;
```

> **不做"合并渲染"**。这是和 07 唯一实质的差别：**一次只查一个 subject**。

### 6.3 接口

```
GET  /api/v1/chat/stream?subject=physics&since=<entryId>    # 某学科空间增量
POST /api/v1/chat               { subject, text, images }   # 发到指定空间
GET  /api/v1/overview           → { subjects:[{key,name,pending,dueCards,lastActive}], lastSubject }
GET  /api/v1/kp?subject=        # 知识点：默认当前科，可 all
GET  /api/v1/mistakes?subject=  # 同上
```

`lastSubject` 用来实现"切回来还记得"。**默认进入「全部」**（一眼看清哪科有事），而不是某科——因为早上你最需要的是全局。

### 6.4 数据侧要注意的一件事

**跨科的知识点绝不能混在一棵树里。** `kp.subject` 是硬约束：

```sql
-- 先修边只能在同一学科内
CREATE TABLE kp_edge (
  ...
  CHECK (1=1)  -- 实际用触发器：from_kp.subject = to_kp.subject
);
```

跨科的"软关联"（物理的函数图像 ↔ 数学的二次函数）**单独一张表**，只用于提示，**不参与先修闸门计算**：

```sql
CREATE TABLE kp_cross_ref (from_kp TEXT, to_kp TEXT, note TEXT, PRIMARY KEY(from_kp,to_kp));
```

> 这条很重要：如果允许跨科先修边进主图，**物理的"函数图像"会变成数学"二次函数"的前置节点，然后两棵树的调度会互相锁死**。

## 8. 一句话记住

> **你和她是"一个人"，但你有"九本笔记"。**
> 分的是聊什么，不是"你是谁"。所以：**没有新建对话、没有会话列表、她只有一个** —— 只是你现在有九个可以各自往下长的空间，切换器在顶栏那一个胶囊上。

## 9. 落地顺序

| 阶段 | 做什么 |
|---|---|
| **M1** | `subject` 字段贯穿始终（消息/知识点/错题都带）；顶部胶囊 + 「全部」概览；先只开**物理**一个空间（九科后补） |
| M2 | 开到 3–4 科（物理/数学/英语/化学）；每科一棵知识点树 |
| M3 | 九科全开 + `kp_cross_ref` 软关联 |
