# 24 · 录入流水线（M1）· 方案与骨架

> 2026-11-15。目标：**拍 10 页卷子，20 分钟内变成结构化题目**（README §9 的 M1 验收）。
> 本文回答：用什么引擎、怎么分段、怎么保住正确率、体验怎么做。

---

## 1. 先定调：瓶颈不是「认字」，是「恢复题目关系」

参考 [合合信息的试卷智能解析实践](https://cloud.tencent.com.cn/developer/article/2724573)（开源样例：[intsig-textin/xparse-sample-projects](https://github.com/intsig-textin/xparse-sample-projects)）：

> OCR 能给的是段落、表格、图片、页码；**下游真正要的是**：哪些内容属于同一题组、哪段是共享题干、图片归表格属于题干还是选项、题号/题型/分值、多页内容是不是同一题。
> 所以正确路线是 **文档解析打底 + 大模型补语义 + 后端做稳定化**，三层各做各擅长的。

这条结论和我们 docs/03 的调研一致（「不是二选一，是版面检测 + 区域分派 + LLM 组装」）。

## 2. 引擎选型（2026-11 现状）

| 引擎 | 形态 | 中文/试卷 | 速度 | 许可 | 本机可行性（无 GPU） |
|---|---|---|---|---|---|
| **[PaddleOCR-VL](https://www.paddleocr.ai/latest/index/index.html)**（0.9B VLM） | 版面 + 识别一体 | 强，官方明确支持试卷、23 类版面 | 论文称比 MinerU2.5 吞吐 **+53%** | Apache-2.0 | 需 GPU（CPU 太慢） |
| **PP-StructureV3** | 版面检测 + OCR + 表格/公式 | 强（含试卷版面类） | 端到端 >100 页/秒（轻量） | Apache-2.0 | CPU 可跑但慢 |
| **[dots.ocr](https://huggingface.co/prithivMLmods/dots.ocr-GGUF)**（1.7B VLM） | 版面 + 识别一体，100+ 语言，明确覆盖 exam papers | 强 | 中等 | MIT（社区 GGUF 可跑 llama.cpp） | **CPU 可试**（GGUF） |
| **MinerU 2.5** | 文档 → Markdown/结构化 | 强 | 中 | AGPL 系 | 需 GPU 才舒服 |
| **PDF-Extract-Kit** | 工具箱（版面/公式/表格） | 中 | 中 | 开源 | CPU 可跑，拼装成本高 |
| **云文档解析 API**（合合 TextIn / 阿里 / 百度高精度含公式） | API | 很强（含公式/表格/坐标） | 快 | 商业 | **零环境成本** |

### 2.1 决策

**接口先抽象，后换引擎。** 定义 `OcrProvider`：

```python
class OcrProvider(Protocol):
    async def parse(self, image: Path, *, need_blocks=True) -> ParseResult: ...
# ParseResult: pages[{page_no, width, height, blocks[{type,text,bbox,html}]}], markdown
```

- **MVP 默认 `cloud`**：先用云 API 跑通链路（`docs/03 §3.4` 已定「50 页/天买 GPU 不划算」），因为本机无 GPU、云 API 有坐标和公式；
- **`mock`**：没有 key 时返回可预测的假块，保证链路与界面能被测；
- **`local`（后续）**：dots.ocr-GGUF（CPU 可跑）或 PaddleOCR-VL（有 GPU 后）。换引擎只实现同一个 `parse()`。

> 这条设计的价值：**OCR 是最可能被换掉的一层**（docs/04 §1），把它隔离成可替换实现。

## 3. 流水线（七个步骤）

```
拍（平板前摄 + 顶部镜面，实时框题）
  → 上传（可连拍、可离开）
  → 文档解析（OcrProvider → pages/blocks/markdown，带 bbox）
  → 按页重组（每页前加显式分隔符；表格保留 HTML、图片保留 ![](url)、公式保留原样）
  → LLM 抽取题组（groups[{shared_stem, questions[{number,type,score,stem,options}]}]）
  → 后端规范化（JSON 兜底 / 字段清洗 / 组号重排 / 跨页合并）
  → 复核（低置信必进；确认后入库 question / question_kp / mistake / card）
```

### 3.1 三个关键技术点（直接抄合合的做法）

1. **题组契约**：prompt 里明确 `groups[].shared_stem` + `questions[]`，**小题不许重复抄共享题干**；
2. **按页分批 + 跨页续接**：一次别把整份卷子发给模型；每批带「上一批最后一个题组的摘要」，模型可标 `continues_previous`，后端负责拼；
3. **不许改写视觉锚点**：图片 `![](url)`、表格 HTML、公式原样保留——一旦改写成「此处有一张图」，图形归属就丢了。

### 3.2 后端规范化（必须做，否则模型输出不能入库）

- JSON 兜底解析（截断/解释性文字混入）；
- 字段类型清洗（score 字符串→数字、options 空值归一）；
- 组号重排（G1..Gn 连续）；
- 批次合并（同 `continues_previous` 的 group 拼接）；
- **每条题目保留 `source_page` 与 bbox**，复核时能对着原图看。

## 4. 体验（比算法更决定「你会不会用」）

| 环节 | 设计 |
|---|---|
| 拍 | 平板前摄 + 顶部镜面（AGENTS §3.6）；取景框**实时框住识别到的题目**（赤陶描边），拍之前就知道框到了什么 |
| 连拍 | 拍完自动进入下一页；页数计数可见；随时可停 |
| 后台 | 上传即返回，OCR/抽取在后台队列；**可以离开界面去复习** |
| 进度 | 每页四态：`排队 / 解析 / 抽取 / 待确认`；顶部一个总进度（`3/10`），不用转圈 |
| 失败 | 单页可重试；失败原因写清（看不清 / 公式截断 / 网络） |
| 复核 | 卡片式：题目 + 原图局部 + 置信度；**低置信必进**；确认后才入库，确认前不污染知识图谱 |
| 先存图 | 允许「先存图、后补字段」——录入永远不该被字段卡住（R2 对策） |

## 7. 正确率的三道保险（不指望模型一次就对）

1. **人工复核队列**：置信度低于阈值必进（R3）；
2. **不改已确认字段**：模型只能建新题、不能改你确认过的答案；
3. **原图可回溯**：每题带 `source_page` + bbox，复核时点一下就能看原图局部。

## 8. 本机现状与第一步

- 本机**无 GPU**、无 OCR 环境（Paddle 未装）；Node/Python 可用，网络可达。
- 所以：**M1.1 先用 mock 跑通状态机与界面**，同时把云 API key 配好就切 `cloud`。
- 一旦有 GPU 或换机器，实现 `local` provider（dots.ocr GGUF 或 PaddleOCR-VL）即可，**上层不动**。

## 9. 改用 DeepSeek 官方 OCR（2026-11-15 实测）

用户提醒后查了 DeepSeek 全家桶的应用 API，确实有两条我们能用：

| 接口 | 用途 | 计费 |
|---|---|---|
| `POST /v1/tools/ocr` | **逐页 OCR**（图片/PDF/Word/PPT），返回每页文本 | **1.5 元 / 1000 页** |
| `POST /files`（`purpose=text_recognition` / `rich_layout_recognition`） | 文件解析，拿到 `file_id` 后在对话里引用 | 同 OCR 价位，按页 |

**用 `POST /v1/tools/ocr`**（不依赖 Files API，直接拿文本 + 坐标）。

### 9.1 两个实测坑（已修）

1. **grounding 标记的分隔符是全角 `｜`（U+FF5C）**，不是 ASCII `|`
   - 实际形状：`<｜ref｜>title<｜/ref｜><｜box｜>[[93,102,399,137]]<｜/box｜> 物理·摩擦力专项`
   - 正文在标记**之后**，`ref` 里是类型标签（title/text/table/formula…）
   - 正则必须 `[|｜]` 两种都认；坐标是**归一化 0–1000**（不是像素）
2. `purpose` 只接受 `text_recognition` / `rich_layout_recognition`；传其他字段会 400

### 9.2 实测结果

上传一页「物理·摩擦力」测试页：

```
provider = deepseek-ocr
5 个 block，bbox 全部是归一化坐标：
  [93,102,399,137]  物理 · 摩擦力专项
  [93,160,598,188]  1. 关于摩擦力，下列说法正确的是（  ）
  [93,202,425,228]  A. 方向总与运动方向相反
  [62,335,763,368]  1. 滑块在斜面上匀速下滑，求动摩擦因数。
```

**这意味着复核界面可以直接按 bbox 裁原图局部**——不用再引第三方 OCR。

### 9.3 多模态（Pi 迁移时漏掉的那块，已补）

问题：切到 Pi 后网关只发文字，图片被丢掉。
修法：
- `models.json` 里模型必须声明 `input: ["text","image"]`，且 `cost` 四个字段齐全（缺 `cacheRead/cacheWrite` 会让**整个 provider 失效**，表现为 `model not found`）；
- 网关把附件读成 `ImageContent {type:'image', data: base64, mimeType}`，走 `session.prompt(text, { images })`；
- FastAPI 转发时带上附件绝对路径。

实测：把测试图发给模型 → 「图里主色是 `#B0563A` 赤陶，写着『物理 · 摩擦力专项』…」——视觉链路恢复。

## 10. M1.3 已实现：LLM 题组抽取 + 后端规范化（2026-11-15）

`server/app/services/extract.py`：

- **LLM 优先**：把 OCR blocks 拼成 `【页 1｜类型｜x1,y1,x2,y2】文本` 的行，交给 DeepSeek 输出题组契约 JSON；
- **后端规范化**：JSON 兜底解析、字段类型清洗（score 字符串→数字）、组号重排 G1..Gn、**共享题干去重**（小题开头若抄了 shared_stem 就切掉）、空题过滤；
- **规则兜底**：模型不可用/抽取失败时退回按题号与选项的规则切分，并在 warnings 里写明原因；
- **置信度**：按题数、是否来自 LLM、有无共享题干/选项加权。

实测（一页手造「物理·摩擦力」测试页）：

```
source=llm   paper_title=物理·摩擦力专项   confidence=0.83
G1: #1 choice  opts=1  bbox=[93,160,598,188]  关于摩擦力…正确的是
G2: #1 short   bbox=[61,336,763,369]  滑块在斜面上匀速下滑…
    #2 short   bbox=[61,383,540,413]  已知斜面倾角 $30^{\circ}$，滑块质量 2kg
warnings: 第1题只识别到 A/B/C/D 部分选项（页缺失未补全）；页内缺少大题标题；OCR 把选项并成一行
```

> 注意这些 warnings 是**模型自己报的**——这正是「不猜、交给复核」的设计意图。

## 11. M1.4 已实现：复核界面 + 确认入库（2026-11-15）

### 11.1 交互

- 输入区 **相机按钮** → 拍照/选图 → `POST /capture/pages`（可多选，按 `page_no` 编号）→ 自动进复核页；
- 复核页（L1，`‹ 采集校对`）：左**原图 + 赤陶 bbox 框**，右**可编辑题卡**（题干、选项，逐行），顶部是模型自己报的 warnings，底部「取消 / 确认入库」；
- 多页时按钮变「确认并下一张」，确认后自动跳下一张；
- 已入库的页显示「已入库」且按钮禁用，不会重复写。
- 深链 `#review=<taskId>` 可直接进复核页。

### 11.2 后端

- 新表 `question`（docs/03 §5 对齐）：`stem_md / answer_md / solution_md / qtype / options / source / source_page / bbox / page_path / stem_preview_png`；
- `PATCH /capture/tasks/{id}/groups` 存复核草稿；
- `POST /capture/tasks/{id}/confirm` 把（改过的）题组写成 `question`，`shared_stem` 会拼到小题题干前；**确认前不写库**，不污染知识图谱；
- `GET /questions` / `GET /questions/{id}` 供后续错题本/复习用。

### 11.3 实测

```
上传一页 → review（3 题）
POST confirm → created=3
GET /questions → total=3（物理：1 choice + 2 short，公式 $30^{\circ}$ 保留）
```

界面截图确认：bbox 框与原图文字对齐（之前是相对容器算百分比，图片有留白就会偏，已改成相对图片实际盒子）。

## 12. 改用阿里云切题（2026-11-15）

用户实测阿里云切题效果好、价格低（[云市场 cmapi00042623](https://market.aliyun.com/detail/cmapi00042623)），决定换掉「OCR + LLM 猜题组」。

### 12.1 两个版本

| 版本 | 鉴权 | 价格 | 输入 | 返回 |
|---|---|---|---|---|
| **云市场** `cmapi00042623` | `Authorization: APPCODE <code>` | 167 元/1000 次（首次 0.01 元/500 次） | **base64 数组**（≤5 张）或 URL | 切题坐标 + OCR 文本（扫描版）；另有精细版返回结构化 |
| **官方** EduTutor `CutQuestions` | AK/SK + `workspaceId` | **公测期 1000 次/天免费** | **必须是公网 URL** | 直接结构化：`questions[].info.{stem,option,figure,answer,type,subquestion}` + `pos_list` |

云市场版：
```
POST <控制台复制的调用地址>/educationservice/papercut
Authorization: APPCODE <你的APPCODE>
{"imgList":["<base64>"],"paperType":"question","templateType":"Physics","image_correction":true}
```

官方版：
```
POST https://edututor.cn-hangzhou.aliyuncs.com/service/cutApi?workspaceId=<id>
{"image":"<公网URL>","parameters":{"struct":true,"extract_images":true}}
响应 data 是 JSON 字符串，里面 questions[]：
  pos_list: 8 点多边形（像素坐标）
  info.stem.text / info.option[].text / info.answer[].text / info.type
```

### 12.2 我们的选择

**先用云市场 APPCODE 版**，理由：
1. 支持 **base64**，不需要把图传到公网（官方版要求 image 是公网 URL，本机是内网 IP，传不上去）；
2. 一页一次调用，0.167 元/次，一天 10 页≈1.7 元；
3. 切题结果直接作为题组来源，**LLM 只在需要时补知识点**，不再让它猜题组。

实现：`server/app/services/papercut.py`
- `cut(image_path, subject)`：按 `PAPERCUT_AUTH`（appcode / aksk）选择调用；
- `normalize()`：算法响应 → 我们的 groups（每题一个 group），`pos_list` 多边形 → bbox，**像素坐标归一化到 0–1000**（与 DeepSeek OCR 同一坐标系，复核界面直接可用）；
- 题型映射：选择题→choice、填空题→blank、判断题→judge、问答题/解答题→short、作文题→essay；
- 答案随题保存（`answer` 字段），**不丢**；
- `capture.run_task` 里**优先走切题**：配了 `PAPERCUT_AUTH` 就跳过 OCR+抽取，直接把结果置为 `review`。

### 12.3 配置（等你给 key）

```env
PAPERCUT_AUTH=appcode
PAPERCUT_APPCODE=...
PAPERCUT_ENDPOINT=https://<控制台复制的调用地址>/educationservice/papercut
# 用官方版时再填：
# PAPERCUT_AUTH=aksk
# ALIYUN_AK_ID=...  ALIYUN_AK_SECRET=...  PAPERCUT_WORKSPACE_ID=...
```

### 12.4 已验证 / 待验证

- ✅ `normalize()` 用官方文档样例跑通：填空题 → `blank`，`bbox` 换算正确，答案 `-17` 保留；
- ⏳ 真实调用待 key；拿到后一次跑通即可替换掉 DeepSeek OCR 那条路。
