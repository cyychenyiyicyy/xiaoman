# 03 · 开源项目调查：哪些轮子能直接用

> 调研时间 2026-11-14/15，star 与版本均为当日实测。三路并行调研的原始产出已并入本文。

先给结论，再给证据。

---

## 0. 一张表看完「用现成 vs 自研」

| 能力 | 结论 | 用什么 |
|---|---|---|
| 编辑器 / 富文本 / 公式渲染 | ❌ **绝不自研** | 复用现成（Compose 端用 Markwon/MathJax WebView；服务端只存 Markdown+LaTeX） |
| 间隔重复调度 + 参数训练 | ❌ **绝不自研** | **FSRS**（`py-fsrs` / `ts-fsrs` / `fsrs-rs`），四档评分 API 已同构 |
| OCR / 版面分析 | ❌ **绝不自研模型** | **PaddleOCR PP-StructureV3**（Apache-2.0）为主，VLM 补手写 |
| 知识点树 + 先修边**数据** | ✅ **直接用现成数据集** | `cn-math-taxonomy`（1644 知识点 / 2403 先修边）、EDUKG、MOOCCube |
| 知识库/笔记底座（若要用） | ⚠️ 可选 | **思源 SiYuan**（API 最全、可导出）；或干脆不要，自建最小表 |
| 知识图谱存储 | ❌ 不要图数据库 | PostgreSQL 节点表 + 边表 + 递归 CTE |
| 题目↔知识点关联、错题→卡片生成 | ✅ **必须自研** | 没有任何现成实现 |
| 知识点级调度 + 先修闸门 | ✅ **必须自研** | 只有论文（LECTOR、ConceptLens），无工程实现 |
| 检索编排（切块/embedding/重排/引用溯源） | ✅ **必须自研** | 约 2000–3000 行，正是所有现成项目都做不好的部分 |

## 1. 间隔重复：FSRS 是唯一答案

### 1.1 版本现状（2026-11）

| 项 | 状态 |
|---|---|
| **生产基线** | **FSRS-6**，21 个权重（w0–w20），比 FSRS-5 多出 decay 可训练项和同日复习项 |
| **FSRS-7** | 34–35 个权重、双幂律遗忘曲线、长短期记忆转场。**实现已落地但规格仍在变动**：`ts-fsrs` 6.0.0（2026-10-27）已默认 FSRS-7，可用 `version:'FSRS-6'` 回退；`fsrs-rs` 有兼容层 |
| **Anki 内置** | 23.10 起可选；25.07 起新牌组默认 FSRS-6；最新 26.08 内核为 fsrs-rs 6.6.1，**仍不含 FSRS-7**（官方论坛确认无 PR） |
| **四个库 API 同构** | `py-fsrs` 6.2（含 Optimizer）/ `ts-fsrs` 6.0 / `go-fsrs`（对齐 v6）/ `fsrs-rs`（Rust，带 GPU 训练） |
| **核心 API** | `next_states(card, now)` + `review_card(card, rating, now)` + `reschedule`；卡对象只需 `stability / difficulty / due / elapsed_days / scheduled_days / reps / lapses / state` |

> **建议**：后端用 **`py-fsrs` 6.2 + FSRS-6**（跟 Anki 生产基线一致，规格稳定），**锁精确版本**。FSRS-7 等它进 Anki 再说。这直接省掉你「自研算法」这个最大的时间黑洞。

### 1.2 「按知识点调度」没有现成实现 ⚠️

这是全篇最重要的发现。现状：
- **只有研究**：LECTOR（LLM 概念级调度）、ConceptLens（BKT + FSRS 混合）、把掌握度交给 BKT/DKT 的通用路线；
- **工程近似**只有 Anki 的 note↔card 一对多（一张笔记生成多张卡），但**调度仍按 card 独立**，没有「先修未达标就冻结后继」这回事。

**这意味着「知识点串联」这个你最痛的点，恰恰是必须自研的部分**——但也不是从零：算法用 FSRS，你只需在它上面加一层**知识点级聚合 + 先修闸门**（见 §4）。

### 1.3 同步

- 独立仓库 `anki-sync-server` 已停止维护，服务端并入 `ankitects/anki` 主仓（`cargo install --git … anki-sync-server`，`SYNC_USER1` 配多用户），协议是 protobuf。
- **对你的意义**：不要指望「把自己的系统做成 Anki 同步服务器」。要做互操作，走**导出 apkg**（单向），成本低一个数量级。

## 2. 知识图谱：现成数据比现成代码值钱

| 资产 | 内容 | 价值 |
|---|---|---|
| **`xiaoyang111222/cn-math-taxonomy`** | **1644 个知识点、2403 条先修边、6723 道题**，对齐人教版课标，纯 JSON | ★★★ **最高**。直接解决「知识点树从哪来」 |
| **`THU-KEG/EDUKG`** | 2.52 亿实体 / 38.6 亿三元组，38 个子图，含学科层级 | ★★ 太重，可挑子图 |
| **MOOCCube** | 706 课程、11.4 万概念，含 `prerequisite-dependency.json` | ★★ 先修对语料，可用于训练/校验 |
| **Codeforces `problemset.problems` / `leetcode-problems` JSON** | 字段可照抄：`contestId/index/name/tags/rating`；`title/topics/difficulty` | ★★★ 题库 schema 的成熟范本 |
| **`margrop/wrong-notebook`** | 自托管错题本，AI 识题、知识点标签、掌握度、组卷打印，**直接支持导入 cn-math-taxonomy 的 topics.json** | ★★★ 唯一接近你需求的现成项目，**先读它的代码** |

> **强烈建议**：动工前花 2 小时读完 `wrong-notebook`。它是目前唯一把「错题 + 知识点标签 + 掌握度」串起来的开源实现，你能直接借鉴它的数据结构和 UI 流程，也能看清它**没做**的部分（没有 FSRS 调度、没有先修图、没有主动推送）——那正好是你的增量。

### 教学法依据（不是玄学）

- **Knowledge Space Theory**（Doignon & Falmagne）→ ALEKS 的自适应诊断，是先修闭包与「学习就绪度」的正式理论；
- **CbKST** 把它工程化为 competence structure + 拓扑排序；
- **Concept Map**（Novak）：节点-连线-层级；
- **掌握学习 + 先修闸门**：未通过先修节点，后继卡片降权或不出队。

### 可借鉴的产品设计

- **SuperMemo**：topics 与 items **分离调度**（阅读材料与回忆题各自排程）、incremental reading。**启示：知识点本身也该有「下次处理时间」，不只是卡片。**
- **RemNote**：Concept/Descriptor 框架——层级概念**自动生成卡片**，卡片带概念引用。**启示：卡片应从知识点树自动派生，而非手工建。**
- **Anki**：note/card 分离 + **revlog 全量日志**（训练 FSRS 的唯一数据源）+ 参数按牌组预设。

## 3. 纸质资料 → 结构化：推荐流水线

### 3.1 引擎横评（许可证实测于 2026-11-14，采购/使用前请复核 LICENSE 原文）

| 引擎 | 许可证 | 中文 | 硬件 | 输出 |
|---|---|---|---|---|
| **PaddleOCR 3.7**（PP-OCRv6 / PP-StructureV3） | **Apache-2.0** | 印刷体最强 | CPU 可跑，GPU 更快 | 文本框+坐标、Markdown/JSON |
| **PaddleOCR-VL 1.6**（0.9B） | Apache-2.0 | 强，含手写 | **6G 显存即可** | 版面+Markdown |
| MinerU 4.x | ⚠️ **AGPL-3.0 含附加条款**（GitHub 识别为非标准） | 强 | GPU 优先 | Markdown/JSON/LaTeX |
| Surya | **Apache-2.0（2026 年从 GPL 放宽）** | 中上 | 8G+ | 行/框/LaTeX |
| marker | **Apache-2.0（同上）** | 中上 | 8G+ | Markdown/JSON |
| Docling (IBM) | MIT | 中（中文一般） | CPU 友好 | DocTags/Markdown |
| RapidOCR | Apache-2.0 | 好（PP-OCR 转换） | **纯 CPU** | 框+文本 |
| Tesseract | Apache-2.0 | 弱（chi_sim 差） | CPU | 纯文本 |
| olmOCR 2 (7B) | Apache-2.0 | 中（英文强） | 16G+ | Markdown |
| dots.ocr (~1.7B) | MIT | 好 | 6–8G | 版面+阅读顺序 |
| **Qwen3-VL 系**（4B/8B/30B-A3B） | Apache-2.0 | 强 | 8G/24G | 任意 schema |

**AGPL 边界**：MinerU 只做**校内/个人自用、不对外提供解析服务**，一般不触发分发义务；一旦做成对外服务或 SaaS，AGPL §13 会要求向使用者提供完整源码。marker/surya 转 Apache-2.0 后已无此问题——**这是今年最值得注意的变化**。

### 3.2 试卷结构的四个难点

| 环节 | 做法 | 坑 |
|---|---|---|
| **切题** | PP-StructureV3 出区域框 → **题号正则（`1.` / `（1）` / `①`）+ 横线/留白投影**切分 | 比纯模型可靠得多。题目跨栏、跨页是主要失败源 |
| **选项配对** | **必须保留 bbox**：按 y 聚类成行、x 判定 A/B/C/D 列 | 不要靠文本流顺序，双栏会全乱 |
| **公式** | UniMERNet（Apache-2.0，~0.5B）或 pix2tex → LaTeX，**输出后必须编译校验** | 行内混排、上下标、根号分数易错；不可编译时降级为「裁剪图 + 占位」 |
| **手写 / 答案区** | 传统 OCR 基本不可用 → **Qwen3-VL-8B 局部裁剪** | 低年级连笔、涂改、答案写在题缝里；答案与题目常分册，按题号对齐错了会把对的判成错的 |

**版面其它坑**：答题卡框线会被当成表格；几何图/图片题无法文本化（只能存图 + 标注）。

### 3.3 两条路线的真相：不是二选一

| | 端到端 VLM 读图 | OCR→LLM 文本化 |
|---|---|---|
| 印刷体准确率 | 95%+ | **97%+**（字符级） |
| 手写/公式 | **明显更好** | 容易崩 |
| 单页 token | 3k–5k | 1.5k–2k |
| 成本 | **高 2–3 倍** | 低 |
| 可控性 | 幻觉、漏题、重排 | **坐标确定，可校验** |

**正确形态 = 分派，不是二选一**：

> 版面检测（轻量）→ 区域分派（**印刷体 → PP-OCRv6**，**公式 → UniMERNet**，**手写 → VLM**）→ LLM 按 JSON Schema 组装。

这是唯一能同时压住成本和准确率的做法。

### 3.4 成本（50 页/天 ≈ 1500 页/月）

| 方案 | 单页 | 50 页耗时 | 月成本 |
|---|---|---|---|
| 3060 12G，8B int4 VLM | 20–35 s | 20–30 min | 电费 ≈ ¥15 |
| **3060，纯 OCR 链路** | **1.5–3 s** | **≈2 min** | **≈ ¥2** |
| 4090 24G，8B bf16 | 4–7 s | 4–6 min | 电费 ≈ ¥25 |
| 4090，30B-A3B int4 | 8–12 s | 8–10 min | 同上 |
| 国产多模态 API | ¥0.01–0.05 | — | ¥15–75（旗舰 ¥150–450） |
| 海外 API | $0.01–0.05 | — | $15–75 |

> 4090 整机约 ¥1.2 万，按 3 年折旧即 **¥330/月——比中档 API 贵**。50 页/天属于典型「**先 API 验证、量涨到 500 页/天再上本地**」的场景。你没有 GPU 就先用 API，别为这个买卡。

### 3.5 推荐 pipeline（七步）

```
1. 预处理   300dpi 灰度、去阴影、拉直、裁边（OpenCV）
2. 版面+切题 PP-StructureV3 出框 → 题号正则切题 → 人工抽检
3. 文本     PP-OCRv6（印刷体），坐标入库
4. 公式     UniMERNet → LaTeX → 编译校验
5. 手写答案 Qwen3-VL-8B 局部裁剪，只读答案区
6. 组装     本地 Qwen3-8B 按 JSON Schema 输出（题干/选项/答案/分值/知识点/置信度）
7. 质检     置信度低于阈值进人工队列 ← 这一步不能省
```

## 4. 必须自研的五个东西（这是你的真正工作量）

| # | 能力 | 为什么没轮子 | 复杂度 |
|---|---|---|---|
| 1 | **题目↔知识点多对多加权标注 + 主知识点** | 题库类产品不公开 schema | 低（表 + 标注 UI） |
| 2 | **错题 → 卡片的生成与去重**（变式、举一反三） | 没人做 | 中（LLM + 相似度） |
| 3 | **知识点级调度**：card 级 S/D 聚合为 kp 掌握度 | 只有论文 | **高（核心壁垒）** |
| 4 | **先修图上的每日队列排序**（拓扑 + 预算 + 复习压力） | 只有论文 | **高** |
| 5 | **掌握度沿先修边的传播衰减模型** | 无 | 中（要调参，且必须留 revlog 可复算） |

## 5. 推荐数据模型（PostgreSQL / SQLite 通用）

```sql
-- 知识点树 + 先修边（DAG）
CREATE TABLE kp (
  id TEXT PRIMARY KEY, code TEXT UNIQUE, subject TEXT, stage TEXT,
  name TEXT NOT NULL, parent_id TEXT REFERENCES kp(id), level INT,
  mastery REAL DEFAULT 0, created_at TIMESTAMPTZ
);
CREATE TABLE kp_edge (
  from_kp TEXT REFERENCES kp(id), to_kp TEXT REFERENCES kp(id),
  type TEXT CHECK (type IN ('prereq','part_of','rel')),  -- prereq = 先修
  weight REAL DEFAULT 1, src TEXT,
  PRIMARY KEY (from_kp, to_kp, type)
);

-- 题目 = Anki 的 note；一题可生成多张卡（多模板）
CREATE TABLE question (
  id TEXT PRIMARY KEY, src TEXT,            -- manual|ocr|web|chat
  src_ref TEXT, title TEXT, stem_md TEXT,
  answer_md TEXT, solution_md TEXT, qtype TEXT,
  difficulty REAL, options_json JSONB, image_paths JSONB, created_at TIMESTAMPTZ
);
CREATE TABLE question_kp (
  question_id TEXT REFERENCES question(id), kp_id TEXT REFERENCES kp(id),
  weight REAL DEFAULT 1, is_primary BOOLEAN DEFAULT FALSE,
  PRIMARY KEY (question_id, kp_id)
);

-- 错题 = 一次「错了」的事实，不是一张卡片
CREATE TABLE mistake (
  id TEXT PRIMARY KEY, question_id TEXT REFERENCES question(id),
  first_wrong_at TIMESTAMPTZ, wrong_cnt INT DEFAULT 1, right_cnt INT DEFAULT 0,
  last_wrong_at TIMESTAMPTZ,
  error_type TEXT,      -- concept|calc|read|careless
  error_note TEXT, image_path TEXT,
  status TEXT,          -- open|reviewing|resolved
  resolved_at TIMESTAMPTZ
);
CREATE TABLE attempt (   -- 每次重做都留痕
  id TEXT PRIMARY KEY, mistake_id TEXT REFERENCES mistake(id),
  ts TIMESTAMPTZ, answer TEXT, correct BOOLEAN,
  duration_ms INT, hint_used BOOLEAN
);

-- 卡片 = 调度单元；字段名照 FSRS 规范，能直接喂库
CREATE TABLE card (
  id TEXT PRIMARY KEY, question_id TEXT, kp_id TEXT, note_id TEXT,
  tpl TEXT,             -- recall|cloze|mcq
  front_md TEXT, back_md TEXT,
  state INT, due TIMESTAMPTZ, stability REAL, difficulty REAL,
  elapsed_days INT, scheduled_days INT, reps INT, lapses INT,
  last_review TIMESTAMPTZ, fsrs_ver INT, param_id TEXT
);
CREATE TABLE review_log (   -- revlog：永不覆盖，训练参数的唯一数据源
  id TEXT PRIMARY KEY, card_id TEXT REFERENCES card(id),
  ts TIMESTAMPTZ, rating INT,            -- 1..4
  state_before INT, state_after INT,
  stability REAL, difficulty REAL,
  elapsed_days INT, scheduled_days INT, kind TEXT, param_id TEXT
);
CREATE TABLE fsrs_param (
  id TEXT PRIMARY KEY, user_id INT, version INT,
  weights_json JSONB, trained_on TEXT, log_loss REAL, created_at TIMESTAMPTZ
);
```

**四条设计要点**：

1. `question` 兼作 Anki 的 `note`：**一题多卡**（多模板），调度仍按 card 独立。
2. `kp.mastery` 是**派生值**（由下挂卡片的 S/D 聚合，可再用 BKT 修正）——不要手工改它，要能随时重算。
3. **错题 ≠ 卡片**：`mistake` 是「我错了」这个事实，`card` 是「我要复习」这个动作。两者生命周期不同（错题可以 resolved 而卡片继续复习）。
4. **先修边存有向边 + weight**，用于掌握度沿边衰减传播。**必须是 DAG**，加边时要检测环。

**几个必须知道的**：
- **Reor 已 archived**，别用于长期项目；
- **Khoj 三个月无推送、无全量导出路径** → 只适合当检索服务，不能当知识库主人；
- **AFFiNE 的 AI 功能绑云端**，自托管后基本没有；
- **Joplin Server 本质是同步后端**，RAG 能力弱。

### 6.2 结论：**不要**把现成笔记系统当核心

对你这套需求，我的建议是**自建最小数据表**（§5 那 8 张表），理由：

1. 你的核心对象是**题目、知识点、错题、卡片**——四类都是**结构化数据**，不是自由文本。笔记系统的强项（富文本、双链、块引用）对你只有 30% 用得上，却要背 100% 的复杂度。
2. 现成系统都缺「复习调度」，你迟早要外挂——**外挂的耦合比自建更贵**。
3. 单用户 + 千级节点，PG 两张表就够。「知识库产品」是给有 10 万条笔记的人准备的。

**唯一值得考虑复用的**：如果你已经有大量思源笔记，那就**只做只读同步**（思源 API 拉取 → 转成 Markdown 存进你的库），而不是把它当主库。

### 6.3 RAG 方案取舍（当你要做「资料问答」时）

| 方案 | 判断 |
|---|---|
| **LightRAG**（41k★，MIT，活跃） | ✅ **个人规模首选**：图 + 向量双检索、支持增量插入、成本低 |
| GraphRAG（37k★，MIT） | ⚠️ 全局型提问最强，但**索引贵、增量更新差**，只适合语料基本固定的场景 |
| nano-graphrag（4k★，2026-01） | 适合改造/教学，不适合生产 |
| **Graphiti**（33k★，Apache-2.0） | ✅ 带时间维度的事实图谱（episode + 有效性窗口），**适合做「你已经会什么、何时错」的学习记忆**；别用它做文档检索 |

### 6.4 Obsidian 插件里值得抄的四个思路

- **Smart Connections**：本地 embedding 索引、无需服务器 → 底座必须提供**相似度查询**，而不是全文搜索。
- **Copilot**：笔记库内 RAG 对话，**引用可点回原文** → **引用溯源是学习类 agent 的关键**，不能只给答案。
- **Excalibrain**：用「父/子/友」等**边类型**导航 → 图谱要带关系类型，不是共现。
- **Dataview**：把 Markdown 当数据表查 → **让 agent 用查询取上下文**，别把全文塞进 prompt，省 token。
