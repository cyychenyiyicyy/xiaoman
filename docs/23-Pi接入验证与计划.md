# 23 · 接入 Pi：验证结果与迁移计划

> 2026-11-15。pi `@earendil-works/pi-coding-agent@1.5.2`，Node 24.19 实测通过。
> 目标：把「对话循环 / provider / 模型目录 / 会话 / compaction / 成本」交给 Pi，我们只写界面 + 工具 + 薄网关。

---

## 1. 已实测（不是照文档抄）

| 项 | 实测结果 |
|---|---|
| 安装 | `npm i @earendil-works/pi-coding-agent@1.5.2`（精确版本），dist 可用 |
| SDK 入口 | `createAgentSession` / `ModelRuntime` / `defineTool` / `SessionManager` 均可从包根导入 |
| 自定义 provider | 在 `models.json` 写 `providers.deepseek = {baseUrl, api:"openai-completions", apiKey:"$DEEPSEEK_API_KEY", models:[{id:"deepseek-flash"}]}`，`runtime.getModel("deepseek","deepseek-flash")` 命中 |
| 一轮对话 | 事件链：`agent_start → turn_start → message_start → message_update ×N → message_end → turn_end → agent_end → agent_settled` |
| **流式增量的位置** | 在 `ev.assistantMessageEvent`：`type = thinking_start / thinking_delta / text_delta …`，正文在 `.delta` |
| 会话方法（本版本） | `prompt / steer / followUp / subscribe / messages / sessionFile / sessionId / dispose / setActiveToolsByName / model / thinkingLevel / isStreaming` |
| **`getEntries` 不存在** | 文档里的旧接口。增量游标改用 `session.messages` + `sessionFile`（append-only JSONL） |
| 构造参数 | `createAgentSession({ cwd, agentDir, modelRuntime, model, thinkingLevel, tools, noTools })`；`tools: [] + noTools:"all"` 可关掉默认 read/bash/edit/write |

> 关键结论：**Pi 这条路是真的**。它确实替我们兜住循环、provider、流式、会话与 compaction。

## 2. 接入后的职责划分

```
Web / Android
   │ HTTPS / SSE
   ▼
FastAPI（业务：记忆 / 搜索 / 复习 / 图谱 / 统计 / 上传 / 鉴权）
   │ 内网 HTTP（HTTP + SSE 透传）
   ▼
agent/（Node 网关，~250 行）
   │ createAgentSession（每学科一个 session）
   ▼
Pi（循环 / provider / catalog / 会话 JSONL / compaction / 成本）
   │ 工具回调（HTTP 回打 FastAPI）
   ▼
学习工具：memory_search / memory_add / memory_update / memory_delete / web_search /（后续 kp_* / question_*）
```

| 归 Pi | 归我们 |
|---|---|
| 对话循环、流式解析、工具调用协议、重试 | 界面（Web / Android） |
| provider 适配、模型目录、`auth.json`、`models.json` | 学习数据（PG）：记忆、题目、复习、图谱 |
| 会话存储（JSONL）、compaction、成本核算 | 工具实现 + 网关的鉴权与限流 |
| thinking 档位映射 | 模型管理 UI（写 `models.json` 的那一端） |

**我们的 DB 仍是唯一的学习数据源**；Pi 的 JSONL 只负责「这次对话说过什么」。

## 3. 分阶段计划（每阶段可独立验收、可回滚）

### P0 · 网关骨架（0.5–1 天）

- `agent/` 起 Node 服务（Express 或原生 http）：`:8791`
- `GET /health`；`POST /agent/chat`（SSE 透传 Pi 事件为 `meta/text/reasoning/tool/done`）
- 每学科一个 `AgentSession`（`sessionDir=agent/.pi-sessions/<subject>`），进程内 Map 复用
- `models.json` / `auth.json` 由 FastAPI 生成（从现有 provider 表导出）
- **验收**：`curl` 问一句，拿到流式正文；刷新页面再问，Pi 记得上一轮

### P1 · 切流量（0.5 天，带开关）

- FastAPI `/chat` 增加 `PI_GATEWAY` 环境变量：开着就转发网关，关着走现有直连
- 前端零改动（SSE 事件形状保持 `meta/reasoning/text/tool/done`）
- 把 Pi 的 `message_update.assistantMessageEvent` 映射成我们的事件；`thinking_delta → reasoning`，`text_delta → text`
- **验收**：同一句提问，两条路径产出等价（正文、思考、工具来源）

### P2 · 工具搬进 Pi（1 天）

- `memory_search / memory_add / memory_update / memory_delete / web_search` 改为 Pi customTools，实现是 HTTP 回打 FastAPI（`/internal/tools/*`）
- Pi 自己决定何时调；`noTools:"all"` + 只挂我们的工具
- 工具结果写回我们 DB 的 `message.parts`（供界面分步展示）
- **验收**：问「我爱吃什么」→ Pi 调 `memory_search`；问新闻 → 调 `web_search`；两工具同轮可用

### P3 · 会话与压缩交给 Pi（0.5 天）

- 每学科 session 常驻；compaction 用 Pi 自带的（它已有 `shouldCompact/compact/generateSummary`）
- 我们停用自己的摘要器，保留 `message` 全量 transcript（导出与回溯用）
- **验收**：长对话（> 模型窗口）能继续、不丢主线；`sessionFile` 增长但请求 token 受控

### P4 · 模型管理对齐 Pi（0.5 天）

- 模型管理 UI 的增删改 → 生成 `models.json`（`baseUrl + api + models`）
- 模型身份仍按 `provider/model` 二元组；目录仍可来自 models.dev
- **验收**：界面加一个端点 → Pi 里能选到并跑通

### 之后回到主线（编码之外的业务）

| 里程碑 | 内容 | 验收 |
|---|---|---|
| **M1 录入闭环** | 拍 → 上传 → OCR → 切题 → LLM 组装 → 确认 → 入库 | 拍 10 页 20 分钟结构化完 |
| **M2 复习闭环** | FSRS + 每日队列 + 四档评分 + revlog | 连续 7 天有队列；评分后 due 正确 |
| **M3 知识关联** | 知识点树 / 先修边 / 掌握度 / 图谱 | 能答「根因在哪」并给先修链 |
| **M4 提问沉淀** | 已是 Pi，转向沉淀与溯源 | 问一次，3 秒后多 1–3 个待复习项 |
| **M5 主动与统计** | ntfy / 周报 / 热力图 / 遗忘预警 | 周日收到周报 |

## 4. 风险与回滚

| 风险 | 对策 |
|---|---|
| Pi 破坏性更新 | 锁 `1.5.2`；只依赖 `createAgentSession/subscribe/prompt/steer/messages`；升级前 worktree 冒烟 |
| 双进程运维成本 | 网关与 API 同机、systemd/compose 编排；健康检查 `/health` 双向 |
| 事件协议漂移 | 网关做一层**稳定映射**（Pi 事件 → 我们的 `meta/reasoning/text/tool/done`），界面不直接认识 Pi |
| 切过去出问题 | `PI_GATEWAY=0` 立即回直连，DB 与前端不变 |
| Pi 无沙箱 | 只挂我们自己的工具（`noTools:"all"`），不挂 bash/read/write |

## 6. P0 / P1 已落地（2026-11-15 实测）

### 6.1 不做 session 常驻（按用户意见修正）

Pi 的会话本来就在 `session.jsonl` 里，**不需要进程内常驻**：
每次请求用 `SessionManager.open(学科文件)` 恢复 → `createAgentSession({ sessionManager })` → 一轮 → 落盘。
`agent/.pi-sessions/index.json` 只存 `学科 → 文件` 映射；新学科首次发言时由 `SessionManager.create` 生成文件后回写映射。

**实测**：
- 第 1 轮在「物理」说「记号是蓝鲸」→ 第 2 轮**新请求**问记号 → 答「蓝鲸」（跨请求恢复成功）；
- 在「数学」问同一记号 → 答「不知道」（学科隔离正确）；
- 两个学科各一个 JSONL，互不污染。

### 6.2 网关（`agent/server.mjs`）

- 纯 Node http，无额外依赖（只有 Pi 本体）；
- `GET /health`、`POST /agent/chat`（SSE）；事件映射成我们的形状：`meta / reasoning / text / tool / done / error`；
- Pi 的 `message_update.assistantMessageEvent`：`thinking_delta → reasoning`、`text_delta → text`。

### 6.3 P1 开关（`PI_GATEWAY`）

`server/.env` 的 `PI_GATEWAY` 非空时，`/api/v1/chat` 改为转发网关；**消息仍由 FastAPI 落库**（user/assistant、`parts`、状态），界面零改动。

**实测**：经网关一轮 → 事件 `meta → reasoning×N → text → done(message_id)`；库里 assistant `status=done`、`parts=[reasoning,text]`。

### 6.4 当前默认

`PI_GATEWAY=`（空）——因为 **P2 还没做：记忆/搜索工具还没搬进 Pi**，此时切过去会丢功能。P2 完成后再把开关设为默认。

## 7. 对照官方 SDK 最佳实践的审计（2026-11-15）

来源：[pi.dev/docs/latest/sdk](https://pi.dev/docs/latest/sdk) 与包内 `examples/sdk/*`（`03-custom-prompt.ts`、`05-tools.ts`、`11-sessions.ts`）。

| 官方做法 | 我们之前 | 现在 |
|---|---|---|
| **用 `DefaultResourceLoader.systemPromptOverride` 换人设** | ❌ 没设 → 跑的是 Pi 自带的「编码 agent」提示词（所以她语气跑偏、会聊网关/工具） | ✅ 写入小满人设（含今天日期 + 当前学科 + 工具边界） |
| **`agent_settled` 才是「不会再自动继续」**（`agent_end` 之后还可能有重试/排队） | ❌ 收到 `agent_end` 就收尾，可能截断重试 | ✅ 只在 `agent_settled` 收尾 |
| 流式中再发消息要 `steer` / `followUp` | ❌ 直接 `prompt`（会抛错或打断） | ✅ `session.isStreaming` 时用 `steer` |
| `subscribe` 要在 `prompt` 之前 | ✅ | ✅ |
| 会话持久化交给 `SessionManager`（open/list/continueRecent） | ✅ 用 `SessionManager.open`，外加一个 `index.json` 存「学科→文件」 | ✅ 保留（学科映射明确），并给 session 设 `sessionName=学科` |
| SDK 会话**不会**自动加载 codemode / tool_search / MCP | ✅ 只有我们的 customTools | ✅ |
| `models.json` 声明 `promptCache` 才会做缓存预热 | ❌ 没声明 | ✅ `promptCache:{short:300}` |
| 把 usage / 成本回传宿主 | ❌ `done.usage` 是空的 | ✅ 从 `message.usage` 映射（input/output/cacheRead/cost） |
| 工具 ≤15 个不必上 tool_search | ✅ 5 个 | ✅ |
| 学科方法论用 skills 惰性加载 | ⏳ 未做 | 待 P4 之后 |

### 7.1 实测（切到 Pi 之后）

- 人设：问「我爱吃什么」→「只知道一件事：你爱吃蛋糕」；问新闻 →「今天（11 月 15 日）…」——不再有编码 agent 腔。
- 工具：`memory_search`（来源 2 条 memory）、`web_search`（来源 5 条 web）、`memory_add`（新增记忆）都在 `parts` 里可回放。
- **缓存**：第 1 轮 4743 token 全 miss；第 2 轮 4803 token 里 **4608 hit / 195 miss，命中 96%**（Pi 的 prompt 结构天然利于前缀缓存）。

> 一句话：现在的接法已经是官方推荐的那条路——SDK 进程内、`SessionManager.open` 恢复、`customTools` 提供工具、`DefaultResourceLoader` 换人设、`agent_settled` 收尾。
> 剩下没做的只有「skills 惰性加载领域方法论」，那属于工具/提示词内容，不是接入方式。
