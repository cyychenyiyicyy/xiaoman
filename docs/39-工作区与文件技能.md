# 39 · 受限工作区与文件技能

> 之前「继续改」是个按钮，必须点它才能把原稿带给模型；不点就像失忆。
> 现在给她一个**按对话隔离的受限工作区**：网页、讲义这些由她自己读写文件完成，
> 下一轮直接 `file_list / file_read / file_edit / publish`，不再需要「继续改」按钮。

代码：`agent/server.mjs`（file tools）· `server/app/api/internal.py`（publish）·
`server/app/services/artifacts.py`（workspace publish）· `agent/skills.json`
· 文档：`docs/38`

---

## 1. 工作区

```
agent/workspaces/<conversation_id>/
  index.html          ← 她自己写的网页
  handout.html        ← 她自己写的讲义
  ...
```

- 每个对话一个目录，跨轮保留；换对话 = 换工作区；
- 目录在 `.gitignore` 里，不进仓库；
- 文件技能只有 **读 / 写 / 改 / 列 / 发布**，没有 shell、没有工作区外的读写。

### 文件工具

| 工具 | 作用 |
|---|---|
| `file_list` | 看工作区里有哪些文件（相对路径 + 大小） |
| `file_read` | 读一个文本文件，改之前先读原稿 |
| `file_write` | 创建/覆盖完整文件 |
| `file_edit` | 精确替换一段原文 |
| `publish` | 把工作区文件发布成资料（HTML）或打印成 PDF |

所有路径都经过 `workspacePath()` 校验：`resolve` 后必须还在当前对话目录里，
`../` 或绝对路径直接拒绝。这是「受限空间」的边界。

---

## 2. 技能：自己生成，不再拼 Markdown

| 技能 | 现在怎么做 | 之前 |
|---|---|---|
| **讲解网页** | `file_write` 写完整 `index.html` → `publish` kind=html | 模型交 Markdown，服务端套模板 |
| **PDF 讲义** | `file_write` 写 `handout.html` → `publish` kind=pdf，服务端 Edge 打印 | 模型交 Markdown，服务端排版 |
| **错题报告** | `question_search` → `file_write report.html` → `publish` pdf | 同上 |
| **知识卡片** | 仍用固定 `make_card`（1080×1440，模板渲染） | 保留 |
| **记忆闪卡** | 仍用固定 `make_flashcards`（翻面卡模板） | 保留 |

也就是说：**除了固定格式的卡片/闪卡，其余产物由 Agent 自己写文件**。
模板只负责卡片这种「必须一卡一点」的稳定版式。

## 3. 上下文不再依赖按钮

第一轮：

```
她：用讲解网页讲一下「离子反应发生的条件」
她：file_list → file_write index.html → publish
```

第二轮（同一个对话，直接说）：

```
她：把标题改得更醒目，其它保持
她：file_list → file_read index.html → file_edit ×2 → publish
```

不再需要点「继续改」。原来的「继续改」按钮已经从预览栏和资料菜单里移除；
`artifact_context` 这套旧逻辑保留做兼容，但正常修改走工作区。

Pi 的会话本身也按对话持久化，工作区文件同时保留；
即使上下文被压缩，`file_list` 仍然能把文件找回来。

## 4. 发布链路

```
Agent file_write(index.html)
        │
        ▼
publish(path=index.html, kind=html)
        │  /internal/tools/publish
        ▼
server 读工作区 HTML → 校验路径 → 写入 data/artifacts/{id}.html
        │
        └── 本轮结束，assistant parts 追加 artifact 卡 → 右侧预览 / 资料库
```

- `kind=pdf` 用同一份 HTML，交给本机 Edge 打印；
- 预览/资料库仍是原来的产物体系，不需要新页面；
- 工作区原文件不删，之后还能继续读、继续改。

## 5. 验收

- **两轮真实链路**（同一个对话）：
  - 第一轮：`file_list → file_write ×2 → publish`，产物 10 KB HTML；
  - 第二轮：`file_list → file_read → file_edit ×2 → publish`，产物更新；
  - 没有点任何「继续改」按钮。
- **PDF 链路**：`file_write handout.html → publish kind=pdf`，215 KB PDF。

- 回归：`ui-hero` 12、资料库 17、技能 7、题库 19、地图 18、主题 12、学习闭环 13；

## 6. 边界

| 项 | 说明 |
|---|---|
| 没有 shell | 只给文件读写，不给 bash；需要命令的能力（如打印 PDF）由服务端工具代劳 |
| 工作区按对话 | 换对话就是新工作区；旧对话的产物仍在资料库，但不在新对话的目录里 |
| 发布是复制 | 工作区文件与 `data/artifacts` 是两份；改工作区后要重新 publish |
| 无版本树 | 每次 publish 生成一个新产物；还没有「版本 1/2/3」折叠 |
| 工作区不清理 | 文件会一直留着；M6 备份/清理时一起处理 |
