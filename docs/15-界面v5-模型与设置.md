## 1. 模型选择：从「一个页面」挪进「输入框」

你说得对——**模型是"这次用什么"，不是"设置里配一次"**。放在设置页里，等于让一个每十分钟可能变一次的选择藏在三级目录后面。

### 新结构

```
┌────────────────────────────────────────────────┐
│  [⚡ v4-flash ⌄]  [✦ 思考·中]        8.2k / 1M │  ← 输入框顶行
│  ＋   📷   🎤    说点什么…                  ↑  │
└────────────────────────────────────────────────┘
```

- **模型胶囊**常驻输入框左上，点开是弹层（不跳页）；
- **思考档位**紧挨着——因为它和模型是一组决策（"用什么脑子 + 想多深"）；
- **上下文占用** `8.2k / 1M` 靠右，`tabular-nums`——你知道还剩多少空间，才敢长聊。

### 弹层内容（V2）

| 元素 | 规则 |
|---|---|
| 模型行 | 图标 + 名称 + 一行规格（**价格 / 上下文 / 一句话特点**） |
| 价格位置 | **必须写在列表里**，不藏详情——自己掏钱，选之前要看 |
| 当前项 | `clayBg` 底 + 白底图标 + 勾 |
| 思考档位 | 关 / 中 / 高，同层切换 |
| 「只对这一科」 | 开关。物理用 pro、其它跟随默认 |

> 设置页仍然保留一个**只读**入口（`模型 · v4-flash ›`），注解写「在输入框里点胶囊也能改」——**同一件事不要有两个可写入口**，这是规范问题。

## 2. 设置页：按组件规范重排

v4 的设置是「一列纯文字 + 右边一句话」，有六个问题：

| v4 的问题 | 违反的规则 |
|---|---|
| 行没有固定高度 | 触控目标 < 48dp |
| 布尔值写成「已开启」文字 | 布尔该用 switch，文字无法一眼扫读 |
| 数值（20 张、2 条）只是文本 | 数值该用 stepper，否则用户以为不可改 |
| 没有分组卡片，只有小标题 | 分组该有容器，否则视觉上全是一坨 |
| 分隔线用整行 | 该用 inset divider（左缩到文字起点） |
| 没有危险操作区 | 破坏性操作必须视觉隔离 |

### 新结构（V3）

```
她
┌──────────────────────────────────────┐
│ ◯ 名字                        小满 › │  56dp
│ ◯ 说话方式                              │
│   先给提示，再给详解                  › │
└──────────────────────────────────────┘
复习
┌──────────────────────────────────────┐
│ ⏱ 每日上限        [− 20 +]           │  stepper
│   超出的顺延到明天                     │
│ ⚡ 目标保留率    ────●──── 0.90       │  slider
│ ✦ 先修未达标时冻结后继        (●)     │  switch
│   没学会前置，后面的卡先不出现          │
└──────────────────────────────────────┘
…
危险操作
┌──────────────────────────────────────┐
│ ✕ 清空所有复习记录                    › │  标题赤陶
│   不动题目与知识点，只删调度历史         │
└──────────────────────────────────────┘
```

### 行组件规格（对齐 design-system 的 component spec 模式）

| 属性 | 值 |
|---|---|
| 行高 | **56dp**（≥48dp 触控要求，带副标题时增高） |
| 左右内边距 | 14 |
| 图标槽 | **24dp 固定**（图标 18，垂直居中） |
| 标题 | 15 / 400，`ink` |
| 副标题 | 11.5 / 400，`ink3`，与标题间距 2 |
| 尾控件 | 右对齐，与图标同列宽纪律 |
| 分隔线 | 1px `line`，**左缩 14、右缩 0**（Material inset divider） |
| 分组卡片 | 1px 描边 + 圆角 10 + 白底 |
| 分组标题 | 11 / 500 + 字距 .1em，`ink3`，上间距 32、下间距 8 |

### 四类尾控件，各管一类

| 数据类型 | 控件 | 为什么 |
|---|---|---|
| 布尔 | **switch**（42×25，开=赤陶） | 一眼扫读状态，且可点 |
| 整数 | **stepper**（− 20 +） | 表明可改，且有边界感 |
| 区间小数 | **slider** + 右侧数值 | 0.90 这种值滑比输入快 |
| 枚举 / 跳转 | **值 + chevron** | 常规导航 |

**危险操作单独一组**，标题用赤陶（`clay`），并且**只有这一处用赤陶文字**——一屏一个强调色，才叫强调。

### 子页也不另起样式（V4）

「通知」子页复用同一套 `sgroup / scard / srow`，只多一个返回箭头。**子页如果自己长出一副新样子，就是不规范。**

## 3. 依据：这次真读了技能

### 3.1 装了哪些

从 `github.com/nextlevelbuilder/ui-ux-pro-max-skill`（**149,263 ★，MIT**）取了 7 个子技能，装进 DSH 的 skills 目录：

| 技能 | 用途 |
|---|---|
| **`ui-ux-pro-max`** | 可检索的设计智能库：80 风格 / 192 配色 / 74 字体对 / **120 条 UX 规则** / 105 图标 / 25 图表 / **22 技术栈**（含 `jetpack-compose`）。带 BM25 检索 CLI |
| **`design-system`** | token 三层架构（primitive → semantic → component）+ 组件规格表 + 状态矩阵 |
| `design` / `ui-styling` / `brand` / `banner-design` / `slides` | 图标/品牌/横幅/演示，本项目用不到，先留着 |

### 3.2 具体用到的规则

| 规则（来自 `pro-rules.md`） | 用在哪 |
|---|---|
| **Touch Target ≥ 48dp**（Android） | 设置行高定 56dp |
| **Consistent Icon Sizing**（定义 icon-sm/md/lg token） | 改成 14 / 18 / 22 三档 + `--stroke:1.7px` |
| **Stroke Consistency**（同层描边一致） | 全稿描边统一为 `var(--stroke)`，脚本验证字面量为 0 |
| **Filled vs Outline Discipline**（同层级只用一种） | 全用 outline（Lucide 线性），不混实心 |
| **8dp spacing rhythm** | 间距收敛为 4/8/12/20/32/52 |
| **Section spacing hierarchy**（明确 16/24/32/48 层级） | 分组上 32 / 下 8 |
| **No emoji as icons** | 全 SVG |
| **Token-driven theming**（禁止裸 hex） | 全走 CSS 变量 |
| **Readable text measure**（大屏不要通篇满宽） | 平板对话栏固定 452dp |

### 3.3 检索遇到的坑（诚实记录）

用它的 CLI 查 `"app settings page grouped list rows" --domain web` → **0 结果**（"Closest known terms: setting, lists"）。按技能自己的要求，我**没有把 0 结果当数据用**，而是：

1. 改成 `--domain ux "settings screen navigation hierarchy"` → 拿到 Heading Hierarchy / Breadcrumbs / Sticky Nav / Font Size Scale；
2. 直接读 `references/pro-rules.md`（技能的 app-UI 交付清单）→ 上面的 9 条规则全出自这里；
3. 字面的「设置页分组列表」这类**没有数据库命中**，是按平台惯例（Material/iOS）补的，规则来源已标注。

> 这条值得记住：**技能有库不等于库里有答案**。0 结果要说 0，然后走已知规则。
