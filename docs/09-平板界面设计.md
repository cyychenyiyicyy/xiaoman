## 0. 一句话

> **平板不是"更大的手机"。手机 = 采集器，平板 = 主界面。**

这个分工不是我替你定的，是你两台设备（讯飞平板 + 小米手机）的自然分工——**举着平板拍卷子很别扭，而在 10 寸屏上校对/复习/看图谱很舒服**。

## 1. 交互模型必须变（这是本节最重要的一句）

| | 手机（compact） | 平板（expanded） |
|---|---|---|
| 点卡片 | **整页替换**（屏幕只够放一个） | **展开到右侧栏**（对话不中断） |
| 形态 | 一个屏 = 一个任务 | **左边过程，右边结果** |
| 好处 | 专注 | **一边问一边看** |

所以 07 说的「功能是消息的展开」，在平板上要升级成：

> **功能是对话旁边的一栏。**

为什么必须这么改，三条理由：
1. **学习本身就是"对话 + 材料"并置**：你问一句 → 旁边摆出知识点链 → 你接着说"那这个呢"，不用来回退。
2. **同屏对照只有宽屏能做**：原图 ↔ 识别结果、题目 ↔ 答案、错题 ↔ 根因。这三组对照是本产品最核心的三个动作。
3. **对话被整页覆盖 = 丢掉上下文**：你看到一半的答案没了，回来还得滚回去。

---

## 2. 三个断点

| 宽度 | 形态 | 导航 | 对话宽 | 卡片去哪 | 代表设备 |
|---|---|---|---|---|---|
| `< 600dp` | compact | **左滑抽屉** | 填满 | 整页替换 | 小米手机（2106118C） |
| `600–840dp` | medium | **rail 保留** | 居中 max 780 | 整页替换（塞两栏会挤） | 竖屏平板 / 分屏 |
| `≥ 840dp` | **expanded** | **rail 76dp** | **固定 472dp** | **右侧栏** | 讯飞平板横屏 |

**判据用窗口尺寸类，不写死像素**：

```kotlin
val wsc = currentWindowAdaptiveInfo().windowSizeClass   // 官方稳定 API
```

你手上那台讯飞平板（`ud710_sa30pro_native`）横屏一般落在 **≈890–1280dp**，也就是 **expanded**——所以**双栏就是你的默认形态**，手机那套反而只是兜底。

> 注意：`androidx.compose.material3.adaptive` 库目前还在 alpha（1.4.0-alpha03）。**用稳定的 `WindowSizeClass` 自己算就行**，别为了省 20 行代码引 alpha 依赖。

## 3. 导航：rail ≠ 会话列表

平板左侧 76dp 导航轨道，**6 项，和手机的抽屉是同一组**：

```
对话 · 错题 · 知识地图 · 她记得的 · 本周 · 设置
```

- 图标 19dp 描边 + 9.5sp 标签，选中态 `clayBg` 圆角 11；
- **产品定义没变**：没有"新建会话"，没有会话列表。rail 只是宽屏放得下所以从抽屉搬到常驻。

> **学科切换器仍在顶栏，不做成 rail 的第二列。** 一旦把九科摊成一条竖列，视觉上就变成"会话列表"了——尽管它语义上是科目。切换器保持那个胶囊，手机与平板同一个控件（见 [11-学科空间设计.md](11-学科空间设计.md)）。

## 4. 逐页平板布局

| 稿 | 页面 | 左栏 | 右栏 | 平板专属收益 |
|---|---|---|---|---|
| **T0** | 对话 + 详情 | 对话 472dp | 知识点详情 | ★★ 问和看同时进行 |
| **T1** | 纯对话 | 对话居中 780dp | 空（留白） | 宽屏不把文字拉成一行 120 字 |
| **T2** | 采集校对 | **原图 + 框选** 600dp | 识别结果列表 | ★★★ 最大收益：边看图边核对 |
| **T3** | 复习会话 | 题干 | 作答/答案（**默认遮住**） | ★★ 想写完再对比，不用来回翻 |
| **T4** | 知识地图 | 全画布 | 浮动节点卡 | ★★★ 窄屏上根本看不了图 |
| **T5** | 错题本 | 列表 432dp | 错题详情 | ★★ 刷列表不丢上下文 |
| **T6** | 本周 | 多列网格 + 两栏 | — | 4 个大数字并排，不拉成一条长滚动 |
| **T7** | 竖屏/分屏 | 对话居中 | 卡片整页打开 | medium 降级验证 |

### 4.1 三条平板专用的布局规则

1. **左栏宽度固定，不按比例分**。对话 472dp 左右最舒服（一行约 30 个汉字）；`0.4 × width` 会在大屏上变成 600+，读起来累。
2. **详情栏的返回栈由"当前选中的卡片"驱动**，不引入独立 `NavHost`：
   ```kotlin
   var selected: CardTarget? by remember { mutableStateOf(null) }
   ```
   点了知识点链的节点 → `selected` 换成该知识点；返回 → 回到上一张卡。**不要用 nav 路由**，因为这不是"页面跳转"，是"同一屏里换右边内容"。
3. **右侧栏顶部固定显示面包屑**（`知识点 / 物理 / 第四章`）+ 一个 `✕` 关闭，把右栏收回纯对话形态。

## 5. 手机端重新定义：采集器（"手机先随便搞一下"的正确做法）

你说手机随便搞一下——**这恰好是对的设计**，因为手机不该做精细活儿。手机只做三件事：

| # | 做什么 | 为什么 |
|---|---|---|
| 1 | **拍照 → 立即上传**（拍完就能放下，不等识别） | 举着手机拍 3 页卷子，多等 1 秒都想放弃 |
| 2 | **系统分享菜单 → 分享到 App → 上传** | 微信/相册/浏览器里看到的东西一键投递 |
| 3 | **上传队列**（成功/失败/重试） | 教室里信号差，必须能重试 |

再加一个**只读的简版对话**（能看到今天安排、能问一句），就够了。

**手机上不做**：校对、复习、图谱、统计、记忆面板——全部留给平板。

> 这就是为什么「手机随便搞一下」不是妥协：**手机上做校对，本来就是错的**。

## 6. 拍照工作流：你两台设备配合起来（这条能把 R2 风险压下去）

```
① 平板上她说：今天还没录入，拍几张？
        ↓
② 你拿手机，连拍 3 页 → 手机上只点「上传」→ 手机可以放下了
        ↓
③ 服务器：预处理 → 版面 → OCR → 切题 → LLM 组装
        ↓
④ 平板上的对话流里，capture_card 自动出现（SSE/推送）
        ↓
⑤ 你在平板上校对（左原图 / 右结果，逐题过）
        ↓
⑥ 确认入库 → 3 道题挂好知识点 → 进复习队列
```

**关键设计**：手机端**不做校对**，只做"投递"。平板收到通知时，卡片上写清"来自手机 · 3 页"。

技术上两行就够：手机上传完成 → 服务端往平板的 SSE 通道推一条 `capture_card`；不在线就走 ntfy 推送。

> 这条是整个产品**录入摩擦**（05 的 R2，最高风险）的主要解法：**拍和校对拆到两台设备上，各自做自己最擅长的那一半。**

## 7. 平板专属的六个优化（手机做不了）

| # | 优化 | 说明 |
|---|---|---|
| 1 | **同屏对照** | 原图↔识别、题↔答、错题↔根因。三处都用双栏 |
| 2 | **草稿区** | 复习时右栏下方留一块演算区，支持手写；写完截图存进 `attempt` |
| 3 | **手写笔** | 讯飞平板自带笔 → 复习时直接手写作答，比打字自然（数学没有键盘友好这件事） |
| 4 | **双指缩放 + 长按取词** | 题目里的图和公式要能放大；长按能选中的文字可以直接问 |
| 5 | **键盘快捷键**（若配键盘） | `Ctrl+Enter` 发送、`1–4` 评分、`Esc` 关右栏、`↑` 编辑上一条 |
| 6 | **分屏共存** | 复习时旁边开课本 PDF —— Android 分屏，App 要正确处理 `onConfigurationChanged`，**别锁横屏** |

## 8. 设备适配清单（针对你那台讯飞平板）

| 项 | 要注意什么 |
|---|---|
| **安装限制** | 学习机通常要家长模式/开发者模式才能装第三方 APK。**包名 `site.e1e.study` 早点占住**，别等做完了才发现装不上 |
| **Android 版本** | 学习机常比主流落后 2–3 代 → `minSdk` 先按题意调查实机版本再定（保守取 **26**） |
| **WebView 版本** | 你在 Ekko Pad 上实测过是 **Chrome 101** → MathJax 3 / KaTeX 都能跑。**公式渲染走 WebView 是安全的**，不需要原生 LaTeX |
| **屏幕比例** | 16:10 横屏（约 1920×1200 / 2000×1200）→ 与我的稿子 1280×800 同比例，双栏宽度可直接照搬 |
| **护眼模式** | 学习机常开护眼（降蓝光）→ 我们的暖白底 `#FAF9F5` 在该模式下仍然可读；**别用纯白 `#FFF` 做大面积底** |
| **强制横屏** | 别在 manifest 里锁 `landscape`，否则分屏会崩。用窗口尺寸类自适应 |
| **大字号/无障碍** | 系统可能开大字号 → 全部用 `sp`，且列表要能随字号变高（别写死 item 高度） |

## 9. Compose 落点

```kotlin
enum class Layout { Compact, Medium, Expanded }

@Composable
fun AppScaffold() {
    val wsc = currentWindowAdaptiveInfo().windowSizeClass
    val layout = when (wsc.windowWidthSizeClass) {
        WindowWidthSizeClass.COMPACT -> Layout.Compact
        WindowWidthSizeClass.MEDIUM  -> Layout.Medium
        else                          -> Layout.Expanded
    }
    var selected: CardTarget? by remember { mutableStateOf(null) }

    Row(Modifier.fillMaxSize()) {
        if (layout != Layout.Compact) NavRail(active = ..., onSelect = ...)   // 76dp
        if (layout == Layout.Expanded) {
            ConversationPane(Modifier.width(472.dp), onCardClick = { selected = it })
            if (selected != null) DetailPane(selected!!, onClose = { selected = null })
        } else {
            ConversationPane(Modifier.weight(1f), onCardClick = { selected = it })
            selected?.let { FullScreenDetail(it, onBack = { selected = null }) }  // 整页
        }
    }
}
```

**三条实现纪律**：
1. **两栏用外层 `Row`**，不要在一个 `LazyColumn` 里塞 `Row`（滚动和测量会打架）。
2. **对话流的 `LazyColumn` 状态要在切换卡片时保留**——`rememberLazyListState` 提到共同父级，否则右栏一开一关，对话就跳回顶部。
3. **关掉 dynamicColor**（Material You 会用壁纸配色毁掉风格），手写 `AnthroLightScheme` / `AnthroDarkScheme`。
