## 1. 参考了哪些开源做法

| 做法 | 出处 | 我们怎么用 |
|---|---|---|
| **回答后异步抽取记忆** | [Mem0 的 memory extraction pipeline](https://docs.mem0.ai/core-concepts/how-it-works) | 每轮回答完，后台抽 0–2 条「她不会的题 / 没懂的点」，去重后写库，可撤销 |
| **Human-in-the-loop 的 "respond" 模式** | [LangGraph interrupt](https://docs.langchain.com/oss/python/langchain/human-in-the-loop)（人类直接回答工具的问题） | 没有阻塞 SSE：工具先返回一张卡，答案作为下一轮消息回来。见 §4.3 |
| **工具调用即 UI** | [Vercel AI SDK Generative UI](https://vercel.com/blog/ai-sdk-3-generative-ui) | `quiz_create` 的结果不是一段文字，而是消息里的 `{type:"quiz"}` part，渲染成可作答卡片 |
| **错题本双泳道 / 知识点聚合** | 之前调研的 `wrong-notebook` | 错题不单开页面，直接并进题库的状态筛选（§6） |

> 为什么不用 LangGraph 那种「暂停等用户」：Pi 网关是一条 SSE 流，工具如果阻塞等作答，
> 流会挂 30 秒以上。改成 **异步卡**：工具立刻返回，用户点选后单独提交，下一轮再讲。

## 2. 数据模型（迁移 `e5a1c8d2f4b6`）

```text
quiz          她出的一道检测题：题干/选项/答案/解析/知识点/状态/作答/来源
deposit       一次自动沉淀：message_id、收了哪些题/点、active|undone、meta
kp_evidence   知识点证据（只追加）：asked | deposit | quiz_right | quiz_wrong + 权重

question + status(learning|weak|mastered) / error_type / next_due_at
         + asked_count / last_asked_at / streak
message  + deposits（消息下面的「已记 错题 1 · 知识点 2 [撤销]」）
```

- `quiz.source`：`agent`（对话工具）/ `question`（题库重做）/ `kp`（按点现生成）/ `nudge`。
- 题目的 `next_due_at` 先用**临时阶梯**（错 → 4 小时，对 → 3 天，连对两次 → 7 天）；
  M2 接 `py-fsrs` 后替换实现，**接口和表结构不动**。

## 3. 自动沉淀（`services/deposit.py`）

### 3.1 流程

```
assistant 消息落库
      │  （独立线程，不挡流）
      ▼
抽 0–2 条 JSON ──▶ 去重（题干指纹 / 附件题 id）──▶ 写 question + question_kp + kp_evidence
      │                                               │
      └── 没抽到但「她带着题说不会」→ 兜底收附件题        └── 消息上挂 deposit 提示条
```

- **不挡流**：用 `threading.Thread + asyncio.run`，而不是 `asyncio.create_task`。
  流式响应结束后请求的 task 可能被回收，线程不会。
- **证据**：题目 → `kp_evidence(kind=deposit, weight 0.9/0.4)`；知识点 → `kind=asked, 0.4`。
- **兜底**：附件里有一道题，且用户说「不会 / 不懂 / 做错 / 怎么做」，即使模型没抽出来也收。
- **不误杀**：短消息（<6 字）、纯问候直接跳过；没有学科（「全部」）不落库，避免脏数据。

### 3.2 撤销

`POST /deposits/{id}/undo`：

- 本次**新建**的题 → 删除（级联删题目标签、quiz 外键置空）；
- 本次**更新**的已有题 → 恢复 `prev_status / prev_error_type / prev_asked_count / prev_due`；
- 删掉这次写的 `kp_evidence`；
- 消息上的提示条变成「已撤销」。

> 撤销必须一次点完，不能要求用户去题库里自己删 —— 否则「自动记」会变成负担。

## 4. 出题检测（`services/quiz.py` + `quiz_create` 工具）

### 4.1 三个入口，一张表

| 入口 | 谁发起 | 题目从哪来 |
|---|---|---|
| 对话工具 `quiz_create` | 她教完一道题 / 你说「考考我」 | 模型自己出（同知识点的变式） |
| 主动消息「出一道检测」 | 每天一次 | 按最近薄弱知识点现生成（LLM） |
| 题库重做 / 待复习 | 用户 | 原题，不重新生成 |

### 4.2 工具约定

```jsonc
quiz_create({
  "stem": "…", "options": ["A. …","B. …","C. …","D. …"],
  "answer": "B", "explanation": "…", "kps": ["离子反应"], "question_id": "可选"
})
```

- 工具把 `conversation_id / assistant_message_id / subject` 从网关上下文带上；
- 服务端建 `quiz`，**这一轮结束时**把 `{type:"quiz"}` 追加进 assistant 的 `parts`；
- 系统提示 + `answer-question` skill 规定：出完只说「来，做一道」，**这轮不报答案**。

### 4.3 卡片与判分

- 消息里的 quiz part 渲染成一张卡：题干 + 四个选项；未答时答案/解析不下发；
- 点选项 → `POST /quizzes/{id}/answer` → 判分（选择题按字母，短答按归一文本）；
- 返回正确答案与解析，卡片变成：对/错 + 正确项高亮 + 解析 +「让她讲」；
- 同时写 `kp_evidence(quiz_right/quiz_wrong)`、更新题目的 `asked_count/streak/status/next_due_at`。

### 4.4 出题生成（按知识点）

`auto_from_kp` 用一次 LLM 调用生成单选题；提示词要求只考一个点、四个选项、答案只写字母。
失败返回 409，不硬造题。**开放题**（没有选项）目前只提示「写在纸上」，留给下一轮讲。

## 5. 主动消息（`services/nudge.py`）

- 触发：App 启动后 `POST /nudges/check`；**每天最多一条**（`app_setting.nudge.date`）。
- 内容：到期题数 + 最近 3 天证据最多的知识点，二选一或都有；没有就不发。
- 落点：最近一个对话的最后一条消息，`kind="nudge"`，会话列表预览会把它顶上来。
- 动作：
  - `出一道检测` → `POST /quizzes/auto`（有薄弱点就按点出，没有就从到期题里挑一道重做）；
  - `去题库复习` → 题库按 `status=due` 筛。
- 模板化，不再花一次模型钱；只在她「有东西可说」的时候出现。

## 6. 错题本并进题库

不新增页面，题库就是错题本：

- **状态筛选**：全部 / 待解决 / 在学 / 已掌握 / 待复习（`GET /questions?status=due`）；
- **卡片**：`待解决`（赤陶）、`已掌握`（sage）、错因、`待复习` 角标；
- **详情**：题型 / 学科 / 年级 / 难度 / 状态 / 错因 / 待复习；
- **编辑**：状态、错因可以直接改（`PATCH /questions/{id}`）；
- 答错的检测会把它自动置为 `待解决`，答对两次升 `已掌握`。

## 7. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/internal/tools/quiz_create` | Pi 工具：出题（带对话/消息 id） |
| POST | `/quizzes/auto` | 现出一题：`question_id` \| `kp_id` \| `due` |
| POST | `/quizzes/{id}/answer` | 作答 + 判分 + 证据 + 同步消息 part |
| POST | `/deposits/{id}/undo` | 撤销一次沉淀 |
| POST | `/nudges/check` | 每天一次主动消息 |
| GET | `/questions?status=weak\|learning\|mastered\|due` | 题库状态筛选 |

## 9. 已知限制 / 下一步

| 项 | 说明 |
|---|---|
| 到期是临时阶梯 | 不是 FSRS；M2 接 `py-fsrs` 后替换，`next_due_at` 字段不动 |
| 没有复习页 | 目前「复习 = 重做一道」，四档评分/每日队列还没做 |
| 开放题不能判 | 卡片只提示写在纸上下轮讲；下一步给输入框 + 模型判分 |
| 「全部」对话 | 没有附件学科时沉淀会跳过；下一步让模型从内容判断学科 |
| 主动消息只有模板 | 没有 LLM 生成的开场白；M5 周报可以接上 |
| 撤销边界 | 只恢复「本次更新前」的字段；如果这期间用户又答了题，以最新证据为准 |
